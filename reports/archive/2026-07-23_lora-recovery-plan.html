1.가설과 목표

가설: 소량의 LoRA 복구 학습으로 (a) 무료 경계 config의 잔여 열화를 지우고, (b) 마스킹에서 “붕괴”로 판정된 더 깊은 절단을 무료 수준으로 되살릴 수 있다. 성립하면 CoC+trajectory 유지 압축이 18.1% → 24.1%로 올라간다.

2.학습 설계

2.1 Loss

  • Trajectory (전 config) — Design B 확정: phase21 flow_matching_loss(release 컨벤션과 동일: t~U(0,1), x_t=(1−t)noise+t·x1, v_target=x1−noise)를 그대로 import. cache를 attached로 두어 단일 backward가 expert LoRA + VLM LoRA를 모두 업데이트 — VLM pruning의 궤적 손상을 cache 경로로 직접 복구. 스모크 실측: VLM LoRA 247/494 params가 nonzero grad, peak 34.6GB(48GB 여유).
  • CoC 문맥 (전 config): teacher(full 모델) reference CoC를 denoise cache의 문맥으로 사용 — 평가 프로토콜(baseline CoC 문맥에서 denoise)과 정합, 매 step rollout 회피(make_teacher_refs로 사전 생성). CoC CE loss(cocsafe 계열만): 같은 teacher 토큰 대상, λcoc∈{0.1,0.5} probe. integrated는 CoC 포기 config라 FM only.
  • Cache distillation은 v1 제외: teacher cache 저장 392GB(불가)·동시 상주 49GB 초과. 후속 2-GPU 옵션으로만 명시.

2.2 LoRA 배치

  • 대상: VLM LM + expert의 모든 잔존 Linear (q/k/v/o, gate/up/down). kv-only layer 35는 k/v proj에 부착(expert가 읽는 cache를 만들므로 복구 지렛대). ViT·embed·lm_head·action proj 동결.
  • r=32, α=64, dropout 0. 학습 파라미터 108.7M(1.37%). peft(0.19.1) 사용 — slim의 수술된 nn.Linear는 표면(이름) 유지라 peft가 투명하게 wrap함을 스모크로 확인(MethodType forward가 self.q_proj를 그대로 호출, layer35 kv-only는 q_proj=None으로 자동 스킵). phase21 lora_target_modules를 q/v→q/k/v/o+gate/up/down로 확장.
  • 학습 후 merge (W += BA) → slim shape 불변 → graph 실측 1.62×/1.43×가 그대로 적용(복구의 latency 비용 0). merge본을 기존 save_slim 형식으로 저장.

2.3 데이터·최적화·메모리

  • train split 900 clips (test 150은 봉인 유지). teacher CoC는 사전 생성(make_teacher_refs.py, full 모델 rollout, 4-GPU 샤딩 ~30분, 텍스트라 저장 무시 가능).
  • AdamW lr 1e-4 cosine(warmup 50), batch 1 + grad accum 8, ~2,000 step(≈2.2 epoch), bf16 base + fp32 LoRA.
  • 메모리 게이트: gradient checkpointing은 use_cache 충돌(P1 확인)로 불가 → 비활성. 예상 peak: slim 16–18GB + activation/grad ≈ 34GB < 49GB. 학습 첫 스텝에서 실측 확인 후 진행(초과 시 prompt 길이 축소가 아니라 accum 유지 + 첫 대응은 expert-only backward 단계 분리).
  • 250 step마다 val probe(10 clips, K=1 minADE + NLL) — 조기 종료·과적합 감시. outputs 규약(config/metrics/summary/plots) 준수.

3.평가 프로토콜

  • 본 평가: 기존 80 clips(val 50 + 회전 33 확보분) × K=8, 동일 클립 순서·seed 공식(42+ci·100+k) → 기존 실행들의 저장된 baseline per-clip 값과 paired 비교 가능(baseline 재측정 불요). paired bootstrap CI, 회전 버킷, p95, regression 수.
  • 비교 3점 세트: 마스킹(복구 전) vs slim(복구 전, =동등) vs slim+LoRA(복구 후).
  • test split(150) 확정 수치: R2 완료 후 최종 채택 config들(integrated 복구본, cocsafe_r20 또는 r30 복구본)에 대해 1회만 실행 — 봉인 해제는 이때가 처음.
  • 보고서: reports/ HTML, 학습 곡선 + 복구 전후 CI 표 + (성공 시) “복구 포함 압축 한계” 갱신.

5.실행 순서·비용

  1. teacher refs 사전 생성 (4-GPU × ~30분)
  2. λcoc probe (cocsafe_r20, 300 step ×2, ~30분)
  3. R1: integrated + cocsafe_r20 병렬 학습 (Ada 2장, 각 ~2시간) → eval (~40분/config)
  4. R2: cocsafe_full_r30 slim 생성(~10분) → 학습 → eval
  5. test split 1회 (채택 config, Blackwell ~1.5시간) → 최종 보고서 + 종합 보고서 갱신

총 예상: 구현 ~1.5일, GPU ~10시간. 위험: FM 학습 loss의 release 훈련과의 정합(구현 시 FlowMatching API 확인, P1 코드 재사용으로 완화), 900-clip 과적합(val probe 조기 종료), λ 민감도(probe로 완화).
