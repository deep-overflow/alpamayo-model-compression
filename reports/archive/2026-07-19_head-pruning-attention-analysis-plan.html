Head Pruning을 위한 Attention 분석 계획

2026-07-19 · 대상 모델 nvidia/Alpamayo-1.5-10B · 환경 /workspace/alpamayo1.5/.venv · 선행 분석: 2026-07-18_alpamayo1.5-model-structure.html

1.배경과 문제 설정

Alpamayo 1.5의 head pruning은 일반적인 LLM head pruning과 두 가지 점에서 다르다.

  • Head가 결합된 두 개의 stack에 존재: VLM decoder(36 layer × 32 Q head / 8 KV head)와 action expert(36 layer × 16 Q head / 8 KV head). Expert는 VLM의 KV cache를 layer별 1:1로 직접 읽는다.
  • 추론이 두 단계로 구성: (1) autoregressive CoC 생성, (2) 그 KV cache 위에서 10회의 flow matching denoising. Head마다 기여하는 단계가 다르다.

이 구조를 무시한 head importance 분석은 잘못된 순위를 만든다. 따라서 각 head를 실제로 기여하는 단계의 loss로 평가하는 것을 핵심 원칙으로 삼는다.

2.핵심 원칙: head 유형별 평가 신호

Head 유형개수영향 범위평가 loss
VLM Q head36 × 32 = 1,152CoC 생성만 (출력이 cache에 저장되지 않음)CoC token NLL
VLM KV head36 × 8 = 288CoC 생성 + expert가 읽는 KV cache 양쪽CoC NLL + flow matching MSE 합산
Expert Q head36 × 16 = 576Trajectory denoising만Flow matching MSE

최종 지표인 minADE는 개별 head 점수 산정이 아니라 pruning 후 검증에만 사용한다. 사용 loss 신호는 세 가지: (1) CoC token NLL(모델 자체 rollout에 대한 teacher forcing), (2) flow matching MSE(expert의 vector field 예측 오차), (3) minADE(검증 전용).

3.방법 1 — Attention map 통계 분석 저비용 · 해석용 · 최우선 실행

Calibration clip 약 50개(notebooks/clip_ids.parquet에서 선정)에 대해 1회 forward를 수행한다. 모든 self_attn에 hook을 걸어 q_norm/k_norm과 RoPE 적용 이후의 q/k를 받아 attention 확률을 chunk 단위로 재계산한다(flash attention은 attention weight를 노출하지 않으므로 VLM은 eager/sdpa로 실행). 전체 map은 저장하지 않고 head별 스칼라 통계만 누적한다.

수집 통계

  • Modality별 attention 질량: 각 head의 attention이 vision token / 텍스트 / trajectory history token(48개) / attention sink(첫 token)에 배분되는 비율. Input ids에서 token 유형 구간을 복원하여 mask를 구성한다. Vision grounding head, 언어 head, ego-motion head, sink head의 기능적 분류가 가능하다 (sink 위주 head는 고전적인 pruning 후보).
  • Attention entropy (집중형 vs 분산형) 및 평균 attention 거리 (local vs global).
  • Head output norm: o_proj 이전 head별 출력의 평균 norm — 비용이 거의 없는 1차 importance 지표.
  • Expert 전용 분석: expert 각 head의 attention이 자신의 diffusion token 64개와 cache 구간(vision / CoC 텍스트 / trajectory history)에 배분되는 비율. 이는 동시에 expert가 실제로 어떤 VLM layer의 cache를 사용하는지를 보여주어, 이후 layer pruning 결정의 직접적 근거가 된다.
  • 중복성 분석: layer 내 head 쌍별 attention 분포 유사도(Jensen–Shannon)와 head output 유사도(CKA). 개별적으로 중요해 보여도 중복인 head는 pruning 가능하다.

산출물: 통계별 36×32 (VLM), 36×16 (expert) heatmap.

4.방법 2 — 1차 Taylor head importance 핵심 ranking · 권장

Michel et al. / Molchanov 방식. 각 head 출력에 gate 변수 ξ_h = 1을 곱해 두고, calibration set에 대해 importance I_h = |ξ_h · ∂L/∂ξ_h|를 누적한다 (등가적으로 head output과 그 gradient의 내적 절댓값). Backward 1회로 모든 head의 점수를 동시에 얻는다는 것이 mask ablation 대비 결정적 장점이다.

  • VLM head: CoC NLL을 backprop. Expert head: flow matching MSE를 backprop (token 64개뿐이라 저렴).
  • VLM KV head: 두 loss의 합산 점수. KV cache를 computation graph에 유지하면 flow matching loss의 gradient가 cache를 통해 VLM의 K/V로 흘러 들어간다 — 이 cross-model 결합을 정량화하는 것이 이 분석의 차별점이다.
  • 실행 가능성: optimizer state 불필요, batch 1 + gradient checkpointing이면 48GB × 4 GPU에서 여유 있음.

5.방법 3 — Mask ablation 검증 ground truth · 부분 실행

Head를 0으로 마스킹하고 실제 Δloss를 측정한다. 전수 조사는 1,728 head × clip 수만큼의 forward가 필요하므로 다음과 같이 축소한다.

  1. VLM은 KV group 단위(36×8 = 288회)로 먼저 ablation.
  2. 개별 head ablation은 Taylor ranking의 상위/하위 10% 구간에 대해서만 수행.
  3. Expert head는 전수 조사 가능 — 각 시도가 cache된 prompt 위에서 denoising 10회만 재실행하면 되므로 저렴.

방법 1/2/3의 ranking 간 Spearman 상관을 확인하고, Taylor가 ablation과 일치하면 전체 규모에서는 Taylor 점수를 신뢰한다.

6.처음부터 반영할 구조적 제약

  • GQA 단위: VLM Q head는 자유롭게 pruning 가능(KV group당 4개). KV head를 제거하려면 해당 group의 Q head 처리와 expert의 k_proj/v_proj 대응 수정이 함께 필요하다. 점수는 두 단위(개별 Q head / KV group) 모두로 산출한다.
  • DeepStack layer 0–2: vision feature가 residual stream에 주입되는 특수 layer이므로 별도 표기하고 무조건적 pruning 대상에서 제외한다. Layer 0의 sink head도 동일.
  • 재현성: 고정 seed, 동일 clip 집합, num_traj_samples 고정. 최종 minADE 검증용 held-out clip은 분석에 사용하지 않는다.

7.실행 계획

Phase A · 통계 수집 → Phase B · Taylor importance → Phase C · Ablation 검증 + pruning 곡선
Phase내용산출물
A Hook 기반 capture 1 pass로 §3의 모든 통계 수집. A와 B는 동일한 capture 인프라를 공유하므로 함께 구현. Head별 통계 heatmap, 기능적 head 분류표
B Loss 신호별 Taylor importance 산출 (CoC NLL / FM MSE / KV head는 합산). Head importance ranking (Q head 단위, KV group 단위)
C 축소된 ablation으로 ranking 교차 검증 후, 하위 head를 10 / 25 / 50% 비율로 pruning하여 held-out clip에서 minADE 곡선 측정. Ranking 일치도(Spearman), pruning 비율–minADE 곡선

각 실험은 outputs/<exp_id>/에 config.json / metrics.json / summary.txt / plot(.png)을 저장하고, 최종 결과는 Claude 스타일 HTML 보고서로 정리한다.

권장 시작점: Phase A + B 동시 착수. A는 해석 가능성(head의 기능 분류)을, B는 실행 가능한 pruning ranking을 제공하며 두 phase는 capture 코드를 공유한다. 승인 시 세부 구현 계획을 작성한 뒤 구현에 들어간다.
