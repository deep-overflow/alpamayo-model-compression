선택은 수렴했는데 성능은 수렴하지 않는다: 캘리브레이션 크기 × 기준의 2×2

2026-09-06 · nvidia/Alpamayo-1.5-10B 24.0% 압축 4종 · val 500 + test 500 + OOD-val 262 · minADE@6 · RTX 5880 Ada (cvlab20 / cvlab21)

캘리브레이션 추출은 압축 자체보다 큰 요인이었고(n=100 여섯 추출 SD 0.363), 안정성 곡선은 n=2,000이면 유지집합이 잡음 바닥까지 수렴한다고 말했다. 그래서 클립을 20배로 늘리면 추출 문제가 사라질 것이라 예상했다. 사라지지 않는다. 유지집합은 예상대로 수렴하는데 성능은 여전히 0.154 벌어진다. 선택 안정성으로 성능 안정성을 살 수 없다.

1설계와 판정

네 arm은 층당 19 Q head / 7,390 MLP 채널, 제거 2,657,452,032 파라미터, expert·KV 미변경으로 완전히 동일하다. 바뀌는 것은 기준(dual vs maxstep11)과 캘리브레이션 크기(100 vs 2,000) 둘뿐이다. 사전등록 판정셋은 test500, 임계 0.01(G0b 잡음 바닥의 8배).

2먼저 배제한 것 — 서버도, 재료도 아니다

maxstep11 @ st2000의 1.984는 이 저장소에서 측정된 어떤 캘리브레이션 arm보다도 나빴다(직전 최악이 dual_nt_d 1.774). 게다가 calib_100 arm 둘은 cvlab21에서, st2000 arm 둘은 cvlab20에서 측정됐다. 계획서가 스스로 적어둔 한계 — “slim 경로의 서버 간 비트 동일성은 미검증” — 을 먼저 채웠다. 기존 대조 검증은 무압축 baseline에서만 이뤄졌고, slim 체크포인트는 slim_lib의 다른 attention forward(Q head별 K/V gather, num_key_value_groups=1)를 타기 때문이다.

cvlab21에서 이미 측정된 calib_100 arm 둘을 cvlab20에서 같은 50 test 클립으로 재측정했다:

armcvlab20cvlab21페어드 차이일치
maxstep11_u40_v20.96120.9612 0.000050/50 클립, CoC 100%
dual_u40_v20.94070.9407 0.000050/50 클립, CoC 100%

slim 경로도 두 서버에서 비트 동일하다. H1의 서버 교차 한계는 해소됐고, 이 결과는 앞으로 두 서버에 걸친 모든 비교에 재사용된다.

재료도 전수 검사했다:

  • importance_st4000_c2000의 12개 배열 전부 importance_v2 대비 spearman +0.90~+0.998, NaN 0, 크기 동일 자릿수. (coc_exp_*가 0인 것은 CoC 목적이 expert를 채점하지 않는 구조적 성질이다.)
  • 스텝 배열은 v1 대비 +0.9888(q_abs_step) / +0.9865(mlp_abs_step).
  • expert 축은 네 arm 모두 해시까지 동일(576 head / 297,216 채널 전부 유지).
  • 층별 유지집합에 병리 없음(중첩 0.84~1.00), 층 35의 rank_norm 상수 함정도 아님.
  • CoC도 건강하다 — maxstep11 @ st2000의 degeneracy 0.034, empty 0.000 (calib_100판 0.026 / 0.000). 궤적만 나쁘다.

“쉬운 클립까지 균일하게 밀리니 계통 오류”라는 의심도 데이터로 기각했다. cvlab21에서만 측정된 진짜 추출 손상 arm들이 같은 곡선 위에 있다 — dual_nt_e는 p10 0.396 / p50 1.205 / p90 2.050, dual_nt_d는 0.396 / 1.293 / 2.226, maxstep11 @ st2000은 0.369 / 1.393 / 2.425. 균일한 곱셈적 이동이 이 모델에서 캘리브레이션 손상의 정상 모양이다.

4진짜 결과 — 선택은 수렴하는데 성능은 수렴하지 않는다

나머지 절반은 설명되지 않는다. 같은 자연 풀·같은 기준의 중첩 사다리는 n=500에서 1.047에 도달하는데, 4배 큰 st2000은 1.2015로 +0.154 나쁘다. 둘 다 공식 train에서 분포매칭으로 뽑은 큰 캘리브레이션이다.

그런데 안정성 곡선에 따르면 n=2,000에서 서로소 추출 두 개의 유지집합 일치율은 Q 97.08% / MLP 95.68%로, G0b가 무해하다고 실측한 잡음 바닥 (Q 97.22%, 그 churn의 비용은 +0.0012, p=0.68)에 도달한다.

선택 안정성은 성능 안정성을 사주지 않는다. 유지집합은 잡음 바닥까지 수렴했는데 두 큰 캘리브레이션의 성능은 0.154 벌어진다. G4가 n=100에서 관측한 것 (중첩률이 손해를 예측하지 못함, spearman +0.068)이 n=2,000에서도 그대로다.

실무적 함의: “캘리브레이션을 키워 추출 분산을 없앤다”는 방향은 막혔다. 남는 잔차 4~5%가 성능 분산의 대부분을 지고 있거나, 성능 분산이 애초에 유지집합으로 설명되지 않는다. 어느 쪽이든 크기를 늘리는 것으로는 해결되지 않는다.

5maxstep11이 4.4배 더 다치는 이유 — 합집합의 붕괴

max는 합집합이고, 합집합은 구성원이 서로 다를 때만 값을 번다. 클립을 늘리면 10개 스텝 기울기가 공통 신호로 수렴해 서로 닮아진다.

기준 · 축구성원 간 평균 상관합집합 크기
maxstep11 @ calib_100, MLP+0.78501.722×
maxstep11 @ st2000, MLP+0.90221.454×
dual @ calib_100, MLP+0.59951.324×
dual @ st2000, MLP+0.74191.235×

maxstep11의 합집합은 16% 붕괴하는데 dual은 거의 그대로다. dual의 두 구성원은 궤적과 추론이라는 서로 다른 목적이라 불일치가 구조적이지만, maxstep11의 열 구성원은 같은 것을 열 번 본 것이라 그 불일치가 상당 부분 잡음이었다는 뜻이다.

n=100에서 maxstep11이 좋아 보였던 것은 잡음이 다양화 정규화로 작동한 결과일 수 있다. 그 “이득”은 애초에 세 세트 모두에서 유의하지 않았고 (p=0.28 / 0.15 / 0.58), 잡음을 걷어내자 큰 손해로 바뀐다.

이는 znorm11(스텝을 z-score 평균으로 합침) 1.390이 왜 나빴는지와 같은 축이다. 평균은 중복 항의 개수에 취약하고, max는 구성원의 독립성에 의존한다 — 두 실패는 같은 성질의 양면이다.

6한계와 다음

  • 개루프만. 폐루프(alpasim)는 dual @ st2000으로 별도 세션에서 진행 중이다.
  • 크기와 추출이 아직 완전히 분리되지 않았다. st2000이 1.2015인 것이 n=2,000의 성질인지 이 추출의 성질인지 구분되지 않는다. calib_st4000의 앞 500·1000으로 중첩 사다리를 만들면 (per-clip 평균으로 GPU 없이 파생 가능) 갈린다. 빌드 2개 + test500 2개 ≈ 2 GPU-h.
  • 분포매칭의 정도 자체가 변수다. st2000은 weighted L1 0.0015로 이 저장소의 어떤 캘리브레이션보다 공식 train 주변분포에 가깝다 (calib_100은 0.0306). train에 더 충실한 것이 test에 더 좋다는 보장은 없으므로, “과도한 매칭” 자체가 후보 원인이다. 아직 검정하지 않았다.
  • maxstep11은 n=100에서도 유의한 이득이 없었으므로, 이 보고서는 그 기준을 기각한다기보다 애초에 채택할 근거가 없었음을 확인한다.
