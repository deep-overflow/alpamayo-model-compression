# 2차 테일러 점수 — 개선인가 (2026-08-25)

## 배경

우리 중요도는 순수 1차다: 유닛 출력에 값 1의 곱셈 게이트를 걸고 `mean_clips |∂L/∂g|`
(`prune_lib.UnitGates`, 절댓값이 클립 합 안쪽). Tyr-the-Pruner와 LLM-Pruner는 둘 다 2차
항을 쓰는데, **서로 다른 것의 2차**다:

| | 무엇의 2차 | 우리 하니스 결과 |
|---|---|---|
| Tyr/OSSCAR | 레이어 출력 재구성 **대리목적**의 정확한 Hessian (H = ΣXXᵀ) | 선택만 쓰면 **붕괴** (test 2.11, degen 74%) |
| LLM-Pruner `param_second` | **과제 손실**의 대각 경험적 Fisher (g²) | 이 실험 |
| 우리 dual | 과제 손실의 1차 | 현행 |

캘리브레이션 진단(2026-08-16)은 1차 근사의 실제 오차가 **그룹 상호작용**(하-가법성
1/5~1/55)이라고 말한다. 이건 **비대각** 효과이므로 대각 2차항으로는 못 고친다 —
따라서 사전 예측은 "**효과 없음**"이었다.

## 무료 스크리닝 (GPU 0)

`importance_perclip.npz`에 클립별 `|∂L/∂g|`가 있어 제곱하면 `(∂L/∂g)²`가 정확히 나온다.
동일 예산에서 kept-set 겹침:

| | Q head | MLP |
|---|---|---|
| traj 1차 vs 2차 | 0.924 | 0.897 |
| coc | 0.934 | 0.926 |
| **dual** | **0.911** | **0.902** |
| *잡음 바닥(같은 기준, calib 50:50)* | *0.860* | *0.782* |

선택 이동이 캘리브레이션 잡음보다 작다. 다만 연산자 ablation 전례상 이 구간은 애매하다
(0.914 dualsum = 무효과, 0.886 dualprod = +0.142\* 열세)이라 겹침만으로는 닫을 수 없어
arm을 실제로 만들어 평가했다.

## arm

`dual2nd_u40_v2` — dual과 **예산·축·할당·max(rank,rank) 결합이 전부 동일**하고 레이어 내
점수만 `mean (∂L/∂g)²`. `make_slim.build_masks`의 `half()`에 `traj2`/`coc2` 추가.
`param_mix`(g − 0.5g²)는 **부호가 필요한데 우리는 절댓값만 저장**해 재계산 불가(스코어링
재실행 ~1.5h 필요) — 아래 결과를 보면 우선순위 없음.

무결성: 제거 2,657,452,032 정확 일치, 레이어당 Q 19/MLP 7390 보존, expert·KV 불변.

## 결론

**기각.** 예측은 "무효과"였는데 실제로는 세 셋 모두 나쁘고 둘에서 유의하다. 대각 2차항은
비대각 상호작용을 못 건드리면서 클립 축 재가중만 바꿔 잡음을 넣는다 — 겹침 91%/90%인데도
바뀐 소수 유닛이 나쁜 교체였다는 뜻.

**2차 방향은 세 경로 모두 닫혔다**: Tyr식 선택(붕괴), 대각 Fisher(유의 열세),
Tyr식 재구성(개루프 ↑이지만 폐루프 −0.036\*·언어 −27pp, `plans/2026-08-21_dual-global.md`).

부수 확인: 겹침 수치만으로 "효과 없음"을 선언할 수 없다는 규칙이 다시 확인됐다 —
0.91은 무효과(dualsum 0.914)와 유의 열세(dualprod 0.886) 사이 구간이고 이번엔 열세였다.
