# 캘리브레이션 크기 × 기준 — 2×2

날짜: 2026-09-06. 브랜치: `worktree-calib-stability-curve`. 상태: **완료** — 세 세트 전부. 보고서 `reports/evaluation/2026-09-06_calibration-size.html`.

## 왜

오늘까지 세 가지가 따로 확인됐다:

1. **추출은 큰 요인이다** — n=100 추출 여섯 개의 SD 0.363, 압축 자체(+0.052)보다 크다
   (`2026-09-03_calib-draw-variance`).
2. **선택은 n을 늘리면 안정된다** — n=2,000에서 Q churn 2.92%로, G0b가 무해하다고 실측한
   수준(2.78%)에 도달한다 (`2026-09-04_calib-stability-curve`).
3. **기준을 바꾸면 좋아진다** — `dual` → `maxstep11`이 test500에서 0.0147.

그런데 3번은 **n=100에서 측정됐다.** 추출 잡음이 기준 효과의 몇 배인 조건에서 잰 값이므로,
그 개선이 기준의 성질인지 그 추출에서만 나타난 것인지 구분되지 않는다.

**캘리브레이션이 안정된 조건에서도 기준 차이가 남는가?**

## 설계 — 2×2

| | `dual` | `maxstep11` |
|---|---|---|
| **calib_100** (n=100) | 있음 (`slim_dual_u40_v2`) | 있음 (`slim_maxstep11_u40_v2`) |
| **st2000** (n=2,000) | 신규 `slim_dual_u40_st2000` | 신규 `slim_maxstep11_u40_st2000` |

네 arm 전부 층당 19 Q head / 7,390 MLP, 제거 **2,657,452,032**, expert·KV 미변경.
바뀌는 것은 **기준**과 **캘리브레이션 크기** 둘뿐이다.

### 캘리브레이션

`calib_st4000`의 **앞 2,000클립**. 그리디 순서라 prefix가 그 자체로 분포매칭이고, 이를 가정하지
않고 실측했다 — weighted L1 **0.0015**, 같은 풀 무작위 2,000이 0.0281, `calib_100`이 0.0306.

재료:

| | dual | maxstep11 |
|---|---|---|
| 궤적 | `importance_st4000_c2000`의 `traj_vlm_*` | `importance_stepvlm_st2000`의 10 스텝 |
| CoC | `importance_st4000_c2000`의 `coc_vlm_*` | 동일 |

`importance_st4000_c2000`은 4,000클립 per-clip에서 **GPU 없이** 파생했다
(`mean(per-clip) == importance.npz`가 0.000e+00로 성립). 스텝 중요도만 새로 측정했다
(2,000클립, 1장, 6.7시간).

## 빌드 시점의 관찰

| | Q 중첩 | MLP 중첩 |
|---|---|---|
| 캘리브레이션만 바꿈 — dual | 0.9211 | 0.8739 |
| 캘리브레이션만 바꿈 — maxstep11 | 0.9269 | 0.8768 |
| 기준만 바꿈 @ calib_100 | 0.9254 | 0.8965 |
| **기준만 바꿈 @ st2000** | 0.9313 | **0.9358** |

**캘리브레이션을 키우니 두 기준이 서로 가까워진다** (MLP 0.8965 → 0.9358). 잡음이 줄면서 서로
다른 기준이 같은 유닛으로 수렴한다는 뜻이고, 안정성 곡선과 같은 방향이다. 이것만으로도 H2의
방향을 시사하지만, 중첩률이 손해를 예측하지 못한다는 것은 이미 확인됐으므로(G4, spearman
+0.068) 판정은 평가로 한다.

## 가설

- **H1 (크기 효과)**: 같은 기준에서 st2000이 calib_100보다 좋다. 추출 잡음이 줄어든 만큼
  개선되어야 한다. 다만 `calib_100`은 여섯 추출 중 1위였던 **운 좋은 추출**이므로, 개선이
  없거나 작아도 "n이 무의미"하다는 뜻은 아니다 — 그 경우 비교 대상이 이미 좋았던 것이다.
- **H2 (기준 효과의 지속)**: st2000에서도 `maxstep11` − `dual` < 0. 남으면 기준 차이는
  캘리브레이션 잡음과 무관한 성질이다.
  - **반증**: st2000에서 차이가 사라지면, calib_100에서 관측된 0.0147은 **그 추출에서만
    나타난 것**이고 기준 비교 전체를 재검토해야 한다.
- **H3 (상호작용)**: 크기 효과가 기준마다 다르다. `maxstep11`이 스텝별 신호를 쓰므로 잡음에
  더 민감할 수 있다.

**판정**: test500 페어드 중앙값 ΔminADE@6, 임계 **0.01**(G0b 잡음 바닥의 8배). val500과
OOD-val은 방향 일관성 확인용.

## 비용

| | |
|---|---|
| 스텝 중요도 2,000클립 | 6.7 GPU-h (완료) |
| `importance_st4000_c2000` 파생 | 0 |
| 빌드 2개 (`--no-state`) | ~2분 |
| 개루프 6 job (2 arm × 3셋) | ~6 GPU-h → 2장에 **3시간** |

전부 cvlab20. 개루프 평가가 이 서버에서 cvlab21과 **비트 동일**함은 baseline 경로에서 확인됐다
(500/500 클립, CoC 텍스트 100% 일치).

## 한계

- **slim 경로의 서버 간 비트 동일성은 미검증.** calib_100 arm 둘은 cvlab21에서, st2000 arm 둘은
  cvlab20에서 측정된다. 대조 검증은 무압축 baseline에서만 이뤄졌고, slim 체크포인트는
  `slim_lib`의 다른 attention forward를 탄다. 2×2의 **기준 대조는 각 서버 안에서** 이뤄지므로
  영향이 없지만, **크기 대조(H1)는 서버를 가로지른다.**
- `calib_100`이 운 좋은 추출(6개 중 1위)이라 H1의 대조군이 편향돼 있다. n=2,000이 이기지
  못해도 그것만으로 "n은 무의미"가 되지 않는다.
- 개루프만. 폐루프는 별도 세션에서 `dual @ st2000`으로 진행 중이다.

## 결과 (test500, 사전등록 판정셋)

| arm | test500 | val500 | OOD-val |
|---|---|---|---|
| dual @ calib_100 | 0.9498 | 0.8904 | 1.0417 |
| dual @ st2000 | **1.2015** | 1.1960 | 1.2282 |
| maxstep11 @ calib_100 | 0.9351 | 0.8915 | 1.1039 |
| maxstep11 @ st2000 | **1.9843** | 1.9693 | 1.6302 |

세 세트가 방향과 크기를 모두 복제한다 (H1 dual +0.116 / +0.111 / +0.089;
H2 @ st2000 +0.422 / +0.385 / +0.286; H2 @ calib_100은 셋 다 p>=0.15).

- **H1 기각(역전)**: st2000 − calib_100 = dual **+0.1157** [+0.0839,+0.1588] p=1.8e-18,
  maxstep11 **+0.5043** [+0.4018,+0.6472] p=1e-51.
- **H2 기각(역전)**: st2000에서 maxstep11 − dual = **+0.4217** [+0.3451,+0.5114] p=5.2e-53.
  calib_100에서는 −0.0041 [−0.0192,+0.0065] p=0.28로 애초에 유의하지 않았다.
- **H3 채택**: 크기 효과가 기준에 따라 4.4배 다르다(+0.504 vs +0.116).

### 서버 교란은 아니다 — 교차 대조

계획서의 한계 항목("slim 경로의 서버 간 비트 동일성 미검증")을 실측했다.
cvlab21에서 이미 측정된 calib_100 arm 둘을 cvlab20에서 같은 50 test 클립으로 재측정:

| arm | cvlab20 | cvlab21 | 페어드 차이 |
|---|---|---|---|
| `maxstep11_u40_v2` | 0.9612 | 0.9612 | 0.0000 (50/50 클립 일치, CoC 100%) |
| `dual_u40_v2` | 0.9407 | 0.9407 | 0.0000 (50/50 클립 일치, CoC 100%) |

**slim 경로도 두 서버에서 비트 동일**하다. H1의 서버 교차 한계는 해소됐다.
재료도 검사했다 — `importance_st4000_c2000`의 12개 배열 전부 `importance_v2` 대비
rho +0.90~+0.998, NaN 0(`coc_exp_*`가 0인 것은 CoC 목적이 expert를 채점하지 않는 구조적
성질); 스텝 배열은 v1 대비 rho +0.9888; expert 축은 네 arm 모두 해시 동일.

## 해석

### H1은 운 좋은 대조군을 상대한 것이다

`calib_100`은 같은 풀 여섯 추출 중 1위였다. 분포 전체와 비교하면 방향이 뒤집힌다:

| | n | minADE@6 |
|---|---|---|
| n=100 자연 추출 6개 | 100 | 평균 **1.3119**, SD 0.3629, 범위 0.950–1.774 |
| st2000 | 2000 | **1.2015** (6개 중 3개보다 나쁨 = 중앙값) |

st2000은 **전형적인 n=100 추출보다 0.110 좋다.** "n을 늘리면 나빠진다"가 아니라
**"n을 늘려도 운 좋은 추출을 못 이긴다"**이다.

### 진짜 문제는 큰 n에서도 추출이 남는다는 것

같은 자연 풀·같은 기준의 중첩 사다리는 1.348(100) → 1.131(200) → 1.061(300) →
**1.047(500)**으로 단조 개선한다. 그런데 4배 큰 st2000은 **1.2015**로, n=500짜리 다른
캘리브레이션보다 **+0.154 나쁘다.**

안정성 곡선에 따르면 n=2,000에서 서로소 추출 두 개의 유지집합 일치율은 Q **97.08%** /
MLP **95.68%**로, G0b가 무해하다고 실측한 잡음 바닥(97.22%, +0.0012 p=0.68)에 도달했다.
**유지집합은 수렴했는데 성능은 0.154 벌어진다.**

> **선택 안정성은 성능 안정성을 사주지 않는다.** G4가 n=100에서 관측한 것(중첩률이 손해를
> 예측하지 못함, spearman +0.068)이 n=2,000에서도 유지된다. 캘리브레이션을 키워
> 추출 분산을 없애려는 방향 자체가 막힌다.

### maxstep11이 4배 더 다치는 이유 — 합집합의 붕괴

`max`는 합집합이고, 합집합은 구성원이 서로 **다를 때만** 값을 번다. 클립을 늘리면 10개
스텝 기울기가 공통 신호로 수렴해 서로 닮아진다:

| | 구성원 간 평균 상관 | 합집합 크기 |
|---|---|---|
| maxstep11 @ calib_100, MLP | +0.7850 | **1.722×** |
| maxstep11 @ st2000, MLP | **+0.9022** | **1.454×** |
| dual @ calib_100, MLP | +0.5995 | 1.324× |
| dual @ st2000, MLP | +0.7419 | 1.235× |

maxstep11의 합집합은 16% 붕괴하는데 dual은 거의 그대로다. dual의 두 구성원은 궤적과 추론이라는
**서로 다른 목적**이라 불일치가 구조적이지만, maxstep11의 열 구성원은 같은 것을 열 번 본
것이어서 그 불일치가 상당 부분 잡음이었다는 뜻이다. n=100에서 maxstep11이 좋아 보였던 것은
**잡음이 다양화 정규화로 작동한 결과**일 수 있다.

이는 기존 메모(`criterion-aggregation-max-vs-mean`: max의 합집합 성질이 스텝 축 세분화보다
중요)와 같은 방향이고, `znorm11`(스텝을 평균으로 합침) 1.390이 왜 나빴는지도 같은 축에서
설명된다.

## 남은 것

- **직접적인 후속**: `calib_st4000`의 앞 500·1000으로 **중첩** 사다리를 만들면
  (per-clip 평균으로 GPU 없이 파생 가능) "1.2015가 n=2,000의 성질인가, 이 추출의 성질인가"가
  갈린다. 빌드 2개 + test500 2개 ≈ 2 GPU-h.
