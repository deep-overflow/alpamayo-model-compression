# 반복 재캘리브레이션 — 스테이지별 재측정이 원샷 컷을 이기는가

날짜: 2026-08-16 (KST) · 상태: 승인 대기 ·
선행: `plans/2026-08-15_importance-calibration.md` →
`reports/evaluation/2026-08-16_importance-calibration.html`

## 가설

1차 Taylor 스코어는 "지금의 네트워크"에서 잰 국소 미분인데, 39.86%를 한 번에 자르면
스코어를 잰 네트워크와 실제로 잘리는 네트워크가 크게 다르다. 캘리브레이션 진단이 그 간극을
직접 보였다:

- **G-CAL-C**: 실제 컷 규모의 그룹 손상이 단독 손상의 합에서 5~55배 이탈(sub-additive),
  그룹이 클수록 악화. 부분 컷 뒤의 네트워크는 보상으로 재배선되고, 원래 스코어는 그
  재배선을 모른다.
- **dual − traj < 0 (teacher-forced에서도)**: 추론 항이 궤적 Taylor의 동시-제거 사각지대를
  메우는 정규화자로 작동 — 사각지대가 실재한다는 end-to-end 증거.

**H1**: 같은 예산·같은 기준에서, 컷을 3스테이지로 나눠 스테이지마다 마스킹된 모델에서
스코어를 재측정하면 원샷(`dual_u40_v2`)보다 test_500 minADE가 낮다. 재측정은 앞선 컷 이후
하중을 새로 짊어진 유닛을 보호할 수 있고, 원샷은 그럴 수 없다.

## 설계: 1요인 = 스테이징

`dual_u40_v2`에서 **스테이지 수만** 바꾼다. 기준(max(rank_norm I_traj, rank_norm I_CoC)),
calib_100, uniform 할당, expert/KV 미개입, 최종 예산(레이어당 Q 13/32 · MLP 4898/12288 컷,
−2,657,452,032 파라미터), 모델 리비전 7aba829 전부 동일.

```
스테이지 s의 누적 컷 수 (레이어당, floor(K·s/3 + 0.5)):
  Q   : 4 → 9 → 13     (K=13)
  MLP : 1633 → 3265 → 4898  (K=4898)

stage 1: importance_v2 그대로 (마스크 없는 모델의 스코어 — 새 측정 불필요,
         원샷과 같은 출발점) → 컷 4/1633
stage 2: 마스크 적용 모델에서 dual 스코어 재측정 (calib_100 전체) → 생존 유닛 중
         하위를 추가 컷 → 누적 9/3265
stage 3: 재측정 → 누적 13/4898 → make_slim 빌드 → slim_dual_u40_it3
```

- 스테이지 스코어링은 `run_importance.process_clip` 그대로, `PruneMasks`를 먼저 설치한 채
  돌린다. 마스크 hook이 gate hook보다 먼저 등록되므로 마스킹된 유닛의 gate 기울기는
  구조적으로 0 — 이미 잘린 유닛이 순위에 다시 끼어들 수 없다 (`run_imp_calib`에서 두 hook의
  합성이 검증됨).
- CoC 텍스트는 각 스테이지에서 **그 시점 모델 자신의 rollout**을 teacher-force한다
  (run_importance의 원래 방식). 목적함수가 스테이지마다 자기일관적으로 움직인다는 뜻이고,
  이는 설계 의도다 — 명시해 둔다.
- rank_norm과 max 결합은 유지한다. 캘리브레이션 진단의 결론(“rank는 무죄, 병목은 독립
  합산”)이 바꾸라고 말하는 것은 정규화가 아니라 측정 시점이다.

### 구현

1. `run_importance.py`에 `--mask <npz>` 추가 (선택적 PruneMasks 설치, 나머지 동일).
2. 오케스트레이터 `run_iter_prune.py`: 스테이지 루프(스코어 로드/측정 → 컷 확장 → 마스크
   저장 `outputs/iter_dual_u40/stage{s}/`), 최종 kept-index를 `make_slim`이 읽는 형식으로 출력.
3. `make_slim.py`에 저장된 마스크 파일로 빌드하는 분기 추가 (`--config dual_u40_it3`).
4. 평가는 기존 경로 그대로: `run_baseline.py --set test --model outputs/slim_dual_u40_it3`,
   `analyze_baseline.py --compare`.

## 사전 등록 게이트

- **R0 (구현 검증, 실행 전 필수)**: 스케줄을 1스테이지 `[13/4898]`로 두고 돌리면 kept-set이
  shipped `dual_u40_v2`와 **레이어 36개 전부 비트 동일**해야 한다. 실패하면 스테이징 효과가
  아니라 구현 차이를 재게 되므로 중단.
- **R1a (주, 방향)**: test_500 페어드 minADE, `it3 − dual_u40_v2`의 부트스트랩 95% CI 상한
  < 0 → 반복이 이득.
- **R1b (크기)**: 중앙값 ≤ −0.015 m — 원샷의 대가(중앙값 +0.0517)의 ~30% 회복. R1a만 통과하고
  R1b 미달이면 "방향은 맞지만 실용적 이득은 미확정"으로 보고한다 (크기 임계를 지표 바꿔치기
  없이 처음부터 분리 등록 — G1/C1의 교훈).
- **R2 (추론 축 안전)**: CoC 퇴화율 < 5% (C3 계승), nll_self 페어드 델타 병기. 퇴화율이
  원샷(3.0%)보다 높아지면 R1과 무관하게 보고서에 명시.
- **R3 (조작 점검)**: 최종 kept-set과 원샷 kept-set의 중첩률. **> 95%면 R1의 null은 "재측정이
  선택을 거의 바꾸지 않았다"로 귀속**하고 스테이징 효과는 미검증으로 남긴다 — 선택이 안
  바뀌었는데 성능이 같다는 것은 가설 기각이 아니다. < 95%이고 R1 null이면 "선택은 바뀌었으나
  성능 무차별"이 결론이다.
- **조건부 폐루프**: R1a 통과 시에만 alpasim public_2601 150씬 (dual/it3 페어드, ~8h).
  개루프 부호가 폐루프에서 뒤집힌 전례가 두 번 있으므로, R1a 통과를 폐루프 없이 헤드라인으로
  쓰지 않는다.

## 한계 (미리 적어둠)

- **스케줄 미튜닝.** 3등분은 첫 시도값이다. 스테이지 수·간격의 스윕은 R1 통과 후의 일이고,
  실패해도 "3등분이 안 됐다"이지 "반복이 안 된다"가 아니다.
- **greedy 비최적.** 스테이지별 하위 컷은 여전히 greedy다. 재측정은 국소 정보를 갱신할 뿐
  조합 최적화를 하지 않는다.
- **목적함수 드리프트.** 스테이지별 rollout 텍스트가 달라진다. 자기일관적이지만, 손상된
  모델의 텍스트로 스코어를 재는 순환이 생긴다 — 퇴화율이 낮은 영역(24%)이라 위험은 작지만
  스테이지별 rollout 퇴화율을 기록해 확인한다.
- **calib_100 재사용.** 세 스테이지가 같은 클립을 본다. 선택이지 학습이 아니므로 과적합
  위험은 낮고, 평가는 서로소인 test_500이다.
