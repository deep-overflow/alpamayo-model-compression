# 캘리브레이션 클립별 영향도 — 어떤 샘플이 dual의 성능을 흔드는가

날짜: 2026-09-14. 브랜치: `worktree-clip-influence`. 상태: **Stage A 완료** (2026-09-15 02:58 KST, M=64). 보고서: `reports/evaluation/2026-09-15_calibration-clip-influence.html`.

## 왜

캘리브레이션 추출은 이 프로젝트에서 측정된 **단일 요인 중 가장 크다**. 같은 `dual` 기준·같은
예산·같은 축인데 100클립을 바꾸기만 하면 test500 minADE@6가 0.9498에서 1.7742까지 간다
(`outputs/calib_variance`, 6개 추출 sd 0.363). 24% 프루닝 자체가 +0.0955인 것과 비교하면
**추출이 방법보다 크다.**

그런데 지금까지의 접근은 전부 **세트 단위**였다:

| 이미 한 것 | 결론 |
|---|---|
| 추출 6개 비교 (`2026-09-03_calib-draw-variance`) | 분산이 실재, calib_100이 운 좋은 1위 |
| n 사다리 100→2,000→4,000 (`2026-09-06_calibration-size`) | 선택은 수렴하는데 성능은 안 좋아짐 |
| 추출 규칙 3종 × 3 seed (`2026-09-12_action-stratified-calib`) | `se`(조성 층화)가 `rd`보다 −0.153 |
| 세트 속성 21종 회귀 (`plans/2026-09-07_draw-order`) | **전부 무상관 또는 복제 실패** |

마지막 줄이 이 계획의 출발점이다. **세트 속성으로 설명하려는 시도는 21번 실패했다.** 남은
설명 후보는 상관이 아니라 **개입**으로만 닿는다 — 클립 하나하나가 최종 성능에 얼마를
기여하는지를 *직접 재는 것*. 그리고 그건 지금 공짜에 가깝게 가능하다:

**`outputs/importance_v2/importance_perclip.npz`에 100클립 각각의 중요도 배열이 이미 있다**
(`(100, 36, 32)`와 `(100, 36, 12288)`, 목적함수 2종 × 축 6종). 그리고 집계는 단순 평균이다 —
per-clip 평균이 출하 `importance.npz`를 float32 정밀도로 재현함을 확인했다
(max\|diff\| 1.9e-08, rel 1.3e-07). 따라서 **100클립의 임의의 부분집합에 대한 중요도는 GPU
없이 numpy로 정확히 계산된다.** 비싼 건 build(~1분)와 평가뿐이다.

## 가설

**H1 (개별 클립 영향)**: calib_100의 클립들은 최종 성능에 대한 기여가 균일하지 않다. 일부
클립은 포함되는 것만으로 minADE를 재현 가능하게 악화시킨다.

- H1이 참이면: 영향도 상위 클립을 빼는 것만으로 같은 n에서 성능이 개선되어야 한다.
- H1이 거짓이면(= 영향이 전부 잡음 바닥 안): 추출 분산은 **집합적 성질**이고 개별 샘플로
  귀속되지 않는다. 이것도 결론이다 — `n=2,000에서 수렴한 선택도 여전히 나쁘다`와
  `그리디 추출 순서가 결과를 만든다`와 일관되며, "좋은 클립을 고르자"는 방향 자체를 닫는다.

**H2 (구조)**: 영향도는 행동 버킷과 연관된다. 사전 예상 방향은
[[calib-draw-variance-lives-in-cruise]] — nt 추출의 널뛰기가 cruise 버킷에 살았으므로
cruise 클립이 고영향(악화 방향)일 것.

**H3 (추출 순서)**: `2026-09-07_draw-order`는 여섯 추출의 서열이 그리디 선호 순서를 따름을
보였다. `calib_100.parquet`의 **행 순서가 곧 그리디 선택 순서**이므로(어떤 prefix도 매칭됨),
세트 내부에서도 같은 것이 보여야 한다: 영향도가 행 인덱스와 상관.

**H4 (선택 ≠ 성능, 다섯 번째)**: 클립을 뺐을 때의 **유지집합 변화량**은 성능 영향도를
예측하지 못한다. 이 레포는 이미 겹침·재구성 오차·추정량 안정성·계획 자기 일관성 네 번
같은 것을 확인했다(`G4_overlap_vs_delta` spearman +0.068, p=0.81). 이번엔 공짜로 5번째
검정이 붙는다.

## 설계 — 부분집합 datamodel

세트 하나당 재측정이 필요 없다는 점을 쓴다. **M개의 50클립 부분집합**을 뽑고, 각각에 대해
`dual_u40_v2` 레시피를 만들어 평가한 다음, 클립별 한계기여를 다음으로 추정한다:

```
tau_i = mean(y_m | i in S_m) - mean(y_m | i not in S_m)
```

`y_m` = 부분집합 m의 arm이 고정 평가셋에서 낸 **baseline 대비 페어드 평균 minADE@6 델타**.
`tau_i > 0` = 클립 i를 넣으면 나빠진다.

**왜 50인가.** LOO(99클립)는 신호가 1%라 잴 수 없다. 50은 `outputs/calib_stability`가 이미
잰 지점이고(Q 유지집합 중첩 0.884), 선택이 실제로 움직이는 크기다. 크기는 **정확히 50으로
고정**한다 — Bernoulli(0.5) 설계는 \|S\|가 ±5 흔들려 크기 효과가 교락된다.

**페어링이 잡음을 죽인다.** 모든 arm이 같은 평가 클립·같은 clip-derived seed를 쓰므로 arm 간
비교는 클립 단위로 페어드다. `calib_variance`의 n=500 CI 폭에서 역산한 페어드 sd는 ≈0.23이라
150클립에서 arm당 페어드 SE ≈ 0.019 — 예상되는 부분집합 간 신호(≈0.1)의 1/5.

### 규모와 검정력

| 항목 | 값 |
|---|---|
| 풀 | **calib_100 100클립** (출하 세트) |
| M (부분집합) | **64** (1차 32 실행 후 확장, 2026-09-14 지시) |
| 적합 평가셋 | val500의 **앞 150클립** (`--limit 150`, 그리디 prefix라 조성 매칭 유지) |
| 클립별 SE of tau_i | `2*sd(y)/sqrt(M)`. **실측 sd(y)=0.2726**이라 M=32에서 0.096, M=64에서 0.068 |
| 다중비교 | 100개 클립 → **순열 귀무분포**로 max\|tau\| 임계값 (y만 순열, 설계행렬 고정) |
| arm당 평가잡음 | 150클립 페어드 평균의 SE **0.106** (minADE 델타가 두꺼운 꼬리) |
| 버킷 수준 | y를 버킷 카운트에 회귀. M=32 실측 계수 SE ≈ **0.012** |

**검정력이 어디 있는지가 분명하다.** M=12 중간 판독으로 실측한 결과, 개별 클립 tau는
M=64에서도 SE 0.068이고 가법 모형이 성립한다는 가정 아래 참 효과의 sd는 0.055로 추정된다 —
즉 **A1은 통과하기 어렵다.** 반면 버킷 계수는 M=64에서 SE 0.0085라 M=12에서 이미 보인
cruise −0.033을 충분히 분해한다(\|S\|=50 추출에서 cruise 개수가 24.5±2.5로 흔들리기 때문;
초기하 sd 2.51). calib_100 조성은 cruise 49 / decel_stop 18 / accel 16 / turn_right 9 /
turn_left 8. **개별 클립이 잡음에 묻혀도 버킷 수준 답은 나온다** — 계획의 안전판이
실제로 검정력이 있는 층위였다.

평가 클립을 150→500으로 늘리는 쪽은 **효율이 나쁘다**: Var(y)의 15%만 평가잡음이고 85%는
진짜 부분집합 차이라, 같은 GPU 시간이면 arm 수를 늘리는 편이 낫다(실측으로 확인).

## 사전 등록 게이트

- **V0 (계측 무결성, 필수 선행)**: 배치 레시피 빌더가 만든 `slim_meta.json`이 같은 부분집합에
  대해 `make_slim.py --config dual_u40_v2 --importance <dir> --no-state`가 만든 것과
  **완전히 동일**해야 한다(키·인덱스 전부). 불일치면 배치 경로를 버리고 `make_slim.py`를
  64번 돌린다(+96분 GPU). 추가로 전체 100클립 부분집합이 출하
  `slim_dual_u40_v2`의 kept set을 **비트 동일**하게 재현하는지 확인.
- **P0 (검정력 중단점)**: 첫 16 arm 이후 `sd(y)`를 잰다. **sd(y) < 0.03**이면 개별 클립
  해상도가 원리적으로 없으므로 Stage A를 중단하고 버킷 수준 + Stage C만 보고한다.
- **A2 (가법성, 2026-09-14 추가)**: 여상보 쌍의 두 반쪽은 calib_100을 정확히 가르므로
  **어떤 가법 모형 `y_S = mean_{i in S} e_i`에서도 쌍의 y 합은 상수**다. 상수가 아니면
  클립별 분해 자체가 존재하지 않고, tau는 클립의 성질이 아니라 비가법 곡면의 투영이다.
  이 게이트는 A1보다 먼저 읽어야 한다. 고정 클립셋에서 y는 결정론적이므로 관측된 산포는
  구조적이고, chi2는 150클립 밖으로 일반화할 때의 보수적 버전이다.
  **M=12 중간 판독: 쌍 합이 0.174~1.072로 6배, chi2 19.4/5 df, p=0.0016 — 기각.**
- **A1 (H1 주 판정)**: 순열 귀무 대비 `max|tau_i|`의 FWER 5% 초과 여부.
  - 초과 → 개별 클립 영향 실재. Stage B로.
  - 미초과 → H1 기각. 그래도 Stage B는 **버킷 상위/하위**로 축소해 돌린다(집합적 효과 검정).
- **B1 (외표본 검정, 결정적)**: `drop_worst20` − `drop_rand20`(3 seed 평균)가
  **test500에서 음수이고 부트스트랩 CI가 0을 배제**. 무작위 대조 없이 상위 k를 빼서
  좋아지는 것은 **평균 회귀로도 나온다** — `maxstep11` 꼬리 사건이 정확히 그 함정이었다.
- **B2 (서열)**: `drop_worst20` < `drop_best20`, CI가 0 배제. B1보다 강하고, 부호가
  뒤집히면 tau의 추정 자체가 잡음이라는 뜻.
- **C1 (H4)**: Spearman(유지집합 변화량, \|tau_i\|). 사전 예상 = 무상관.

**tau는 val500(적합)에서 추정하고 검정은 test500(외표본)에서 한다.** 같은 셋에서 고르고 같은
셋에서 읽으면 승자의 저주다 — 이 레포가 `maxstep11`에서 한 번 낸 값이다.

## 단계

### Stage A — 64개 부분집합 arm (적합)

1. 설계 생성: seed 20260914, M=64, \|S\|=50 **여상보 쌍**. `design.json`에 클립 인덱스·ID·해시.
   쌍 설계라 모든 클립이 정확히 M/2회 등장하고(SE 균일), **짝수 prefix는 그 자체로 균형**이라
   M을 나중에 늘려도 재균형이 필요 없다.
2. 레시피: 모델 1회 로드 → 부분집합마다 평균 중요도 → `make_slim.build_masks` →
   `slim_meta.json` 기록. 64개 약 5분 (V0 통과 전제; 실측 arm당 0초, 모델 로드 19초).
3. 평가: `run_baseline.py --set indist --limit 150 --model outputs/slim_subinf_<mm>`.
   arm당 ~19분(실측), Ada 4–7 4-way → **약 6.8시간**.

### Stage B — 외표본 검정 (5 arm, test500)

`drop_worst20` / `drop_best20` / `drop_rand20_{a,b,c}` — 전부 n=80, 같은 레시피 경로.
**Stage A 결과를 보고 승인받은 뒤 실행한다.**
test500 전체(500클립), arm당 2샤드 → 10잡 × ~40분 / 4카드 ≈ **1.7시간**.

### Stage C — 세트 속성 재검정 (GPU 0)

같은 64개 (부분집합 → 성능) 쌍으로 `draw-order`가 n=6에서 기각한 세트 속성들을 **n=64**로
다시 건다: 버킷 조성, 평균 `fm_loss`, `coc_len`, 6속성 분포 거리, 출하 dual과의 유지집합 중첩,
점수 모양. 21개 후보가 전부 무상관이었던 것이 검정력 문제였는지 아닌지가 여기서 갈린다.

## 비용

| 단계 | GPU 시간 | 벽시계 (Ada 4–7) |
|---|---:|---:|
| 레시피 69개 | 0.1 h | 5 min |
| Stage A 평가 64 arm | 20.3 h | **~6.8 h** |
| Stage B 평가 5 arm | 6.7 h | **~1.7 h** |
| Stage C + 분석 | 0 | 20 min |
| 합계 | 27.1 h | **~8.8 h** |

**Stage A를 먼저 돌리고 멈춘다.** Stage B 진행은 tau를 본 뒤 결정한다. M은 32에서 시작해
**64로 확장**했다(사용자 지시, 2026-09-14) — 쌍 설계라 앞 32개를 버리지 않고 이어붙인다.

디스크는 사실상 0 — 전부 `--no-state` 레시피(`slim_meta.json` 3.4 MB)다.
**GPU 0–3은 사용하지 않는다**(사용자 지시, Blackwell과 Ada는 값이 다르다).
tau는 running mean이라 **M은 나중에 늘려도 재적합이 필요 없다** — P0에서 sd(y)를 보고
해상도가 아쉬우면 arm을 덧붙이면 된다. 설계는 M=64까지 미리 생성해 두고 앞 32개만 돌린다.

## 검증

1. **V0**: 위 게이트. 배치 빌더 vs `make_slim.py` 메타 완전 일치 + 100클립 부분집합 =
   출하 `slim_dual_u40_v2` 비트 동일.
2. **스모크**: 첫 arm의 150클립 결과가 `dual_u40_v2_ps_indist`의 같은 150클립과
   같은 자릿수인지(50클립 캘리브레이션이므로 다소 나빠야 정상).
3. **결정론**: 전 arm 동일 아키텍처(Ada), `--seed 42`, clip-derived seed. 재실행 비트 동일.
4. **순열 귀무**: 설계행렬 고정, y만 순열 — 고정 크기 설계의 상관 구조가 보존된다.
5. 보고서는 `build_report.py` + 템플릿 규약, `reports/evaluation/`에 HTML 한 편.

| **A2 가법성** | **기각** — 쌍 합 0.0832~1.6886 (20.3배), χ² 144.6/31 df, **p=1.3e−16** |
| **A1 개별 클립** | **실패** — max\|τ\| 0.1275 < FWER 임계 0.1726, 0/100 |
| **A1b 총괄** | **실패** — sd(τ) 0.0525 < 귀무 0.0573 (p=0.901), 신호 지분 **0%** |
| C1 churn↔\|τ\| | **널** (ρ=+0.110, p=0.275) — 사전 예상대로, 다섯 번째 "X는 능력을 예측 못 함" |

**결론**: 추출 효과는 실재하고 거대하지만(전체 100클립의 6.6배, 최악 28.9배) **개별 샘플로
분해되지 않는다.** 검정력 부족이 아니다 — 구조적 분산의 39.6% 이상을 설명하는 가법 구조라면
검출됐을 크기다. 이유는 **가법 구조 자체가 없어서**이고, 기전은 kept set이 점수의 top-k argsort라
평균 중요도의 선형함수가 아니라는 것이다.

H1 기각, H2(버킷) 기각, H3(추출 순서) 기각, H4 예상대로 널. 사전 등록한 안전판(버킷 수준)이
실제로 검정력이 있는 층위였던 것은 맞았으나, 그 층위에서도 효과가 없었다.

### 계획에서 달라진 것

- **여상보 쌍 설계**(계획서 작성 후 변경): 클립별 SE 균일화·정확 무작위화 검정이 목적이었는데,
  실제로 결론을 만든 것은 **계획에 없던 A2**였다. 두 반쪽이 모집단을 정확히 가르면 가법 모형이
  쌍 합에 검정 가능한 제약을 걸고, 추가 실행 없이 읽힌다.
- **A1b 총괄 검정 추가**: `max|τ|`만으로는 "검정력이 부족했나"를 열어둔 채 끝난다. sd(τ)를 같은
  귀무에 걸면 100개를 모두 모으므로 훨씬 예민하고, 두 분산의 차가 신호 지분의 추정치가 된다.
- **M 32 → 64**: 사용자 지시. 검출 가능 per-clip sd 0.050 → 0.028.

### Stage B는 재설계가 필요하다

계획서의 `drop_worst20` 대 `drop_rand20`은 A1b가 τ를 잡음이라 판정한 이상 **잡음으로 고른 집합을
검정**하는 셈이라 널이 예정돼 있다. 같은 1.7시간이면 **최선(+0.0200)·최악(+0.9977) 부분집합의
test500 재현**이 낫다 — 검증해야 할 것은 τ가 아니라 A1b·A2다.

### 후속 가설 (결과 아님)

부분집합 평균 LOO churn이 세트 속성 15종 중 가장 셌고(ρ=−0.340, p=0.006) M=32→64에서 부호를
유지했으나 BH(q=0.091)와 순열 FWER(0.340 < 0.365)를 못 넘었다. 사전 등록 후 독립 표본에서
다시 걸어야 한다.
