# Experiment: KISTI 한강(kisti6, GH200) 평가 사이트 구축과 검증 게이트

계획 `cvpr27/plans/2026-11-05_kisti6-gh200-site.md` · 모델 `nvidia/Alpamayo-1.5-10B`(rev `7aba829`)
· KISTI 한강 `5thEx` 파티션, NVIDIA GH200 120GB · 분석 `cvpr27/code/analyze_gh200_gate.py`(`outputs/cvpr27/gh200/gate/`).

## Purpose
- NEURON A100 큐는 사용자당 실행 잡 2개라 대기가 길다. 한강을 두 번째 GPU 사이트로 쓸 수 있는지 본다.
- 확인할 것:
  - **G1** GH200 경로가 결정적인가(같은 GPU 종류에서 다시 돌리면 같은 결과인가)
  - **G2** GH200과 A100의 차이가 얼마인가(기준 없음, 기록만)
  - **G3** 마스크만 있는 레시피(MoOP l0keep)와 가중치를 다시 쓴 레시피(tyr_off)가 로드되는가
  - **G4** GPU 한 장당 처리량

## Setup
- **하드웨어:** GH200 120GB(사용 가능 97,871 MiB), 드라이버 570.124.06. 호스트 CPU가 ARM(aarch64)이다.
  - 우리 그룹(sa0713)이 쓸 수 있는 GPU 파티션은 `5thEx`(104노드 × 4장)뿐이다.
- **소프트웨어 (A100과 다른 점):**

  | 항목 | A100 (NEURON) | GH200 (한강) |
  |---|---|---|
  | torch | 2.8.0+cu128 | **2.8.0+cu129** (2.8.0의 aarch64 CUDA 빌드가 cu129뿐, 사용자 결정) |
  | Python | 3.12.14 | 3.12.13 (둘 다 uv 관리) |
  | flash-attn | 2.8.3 공식 wheel | 2.8.3 소스 빌드 (sm_90, nvcc 12.9) |
  | transformers / alpamayo1_5 | 4.57.1 / f42e594 | 같음 |
  | 평가 attention | sdpa | sdpa |

- **평가:** `eval_a100.sbatch`(`OUT_SITE=gh200`)와 `run_baseline.py`를 그대로 썼다.
  - 결정적 설정, k=8, seed 42, max_gen 256, rollout만 썼다.
  - @6은 앞 6개 샘플의 최솟값이다.
- **세트:** test_2000의 0번 조각(16분할, 간격 추출) 125클립이다. A100 행과는 clip_id로 짝지었다(시드가 clip id에서 정해진다).
- **잡:** 1225621을 node1796에서 2026-11-06 12:15–12:31 KST에 돌렸다. GPU 4장에서 작업 4개를 동시에 실행했다.

**구축 비용·사건**
- cvlab21에서 데이터 약 65 GB를 보냈다.
  - 모델 hub 22 GB, test 캐시 11 GB, ood 캐시 8.5 GB, LingoQA 7.1 GB, outputs(레시피·목록) 16 GB
  - LingoQA 중 약 6.6 GB는 평가에 쓰지 않는 train 이미지가 섞여 간 것이다(이후 제외하도록 수정).
- cvlab21→KISTI 회선이 20 kB/s와 90 MB/s 사이를 오갔다. 11-06 01:20에는 회선이 무너져 소켓이 끊겼고, 11:24–11:42에 18분 만에 나머지를 보냈다.
- 소켓이 끊긴 뒤 스크립트가 새 로그인을 두 번 시도해, 한강에 인증 실패가 기록됐다(계정은 잠기지 않음).
  - 모든 KISTI 스크립트에 `BatchMode=yes`를 넣었다(`dc23da4`).
- flash-attn 빌드는 세 번째에 성공했다(12분).
  - 1회차: 메모리 부족(nvcc 36개)
  - 2회차: `c++`가 gcc 7.5를 가리키고, 헤더 없는 시스템 Python으로 venv가 만들어짐
- 게이트 잡은 예상(12:45)보다 이른 12:15에 시작했다. 4작업 × 약 14분 ≈ 1 GPU-시간이다.

## Analysis (Opinion)
- **GH200 경로는 결정적이다(G1).** 같은 카드 종류에서 다시 돌리면 bit 단위로 같으므로, GH200끼리 비교한 표는 A100 표와 같은 방식으로 믿을 수 있다.
- **GH200과 A100의 차이는 A100과 Ada 사이 차이와 같은 크기다.**
  - 평균 차이(6.4 s minADE@6): dense +0.004, MoOP l0keep +0.006, tyr_off 0.000 m. 이전 측정에서 A100↔Ada는 dense 0.003 m 이하, MoOP 0.018 m 이하였다.
  - 클립 단위로는 거의 모든 클립이 조금씩 다르고, CoC 문장도 2–7% 클립에서 바뀐다.
  - 따라서 GH200 행은 A100 표에 섞을 수 없다. GH200 표를 만들려면 dense와 기준 arm까지 모두 GH200에서 다시 재야 한다(계획 §2.7).
  - 원인이 GPU 아키텍처인지 CUDA 12.8→12.9 차이인지는 이 실험으로 가를 수 없다.
- **GPU 한 장당 속도는 A100과 비슷하다(2–5% 느림).** 배치 1의 자기회귀 디코딩을 결정적 설정으로 돌리는 구조라 연산보다 지연이 병목이다. 그래서 GH200의 연산 성능 이점이 드러나지 않는다.
  - 한강의 이점은 속도가 아니라 **용량과 대기 시간**이다. 동시에 최대 5잡 × 4장 = 20장을 쓸 수 있다(NEURON은 2잡). 이번 잡은 제출 후 30분 만에 시작했다.
- **다음 단계 제안:**
  - 한강은 "한 표 전체를 GH200에서" 도는 새 실험에 쓴다. dense, MoOP, MoOP l0keep 같은 기준 arm을 먼저 GH200에서 한 번 재 두면, 이후 arm은 그 위에 얹으면 된다.
  - 기존 A100 표를 그대로 늘리는 작업(같은 표에 행 추가)은 계속 NEURON에서 한다.
  - 대용량 전송은 cvlab21 회선 상태에 따라 NEURON→한강 내부망 경로(`cvpr27/code/neuron_to_kisti6.sh`)를 쓴다.
