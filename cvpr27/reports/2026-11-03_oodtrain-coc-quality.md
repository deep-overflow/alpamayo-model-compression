# Experiment: OOD-train 개루프 + OOD CoC 품질 (정답 CoC NLL, Claude 채점) — A100

계획 `cvpr27/plans/2026-11-02_oodtrain-coc-quality.md` · 모델 `nvidia/Alpamayo-1.5-10B`(rev `7aba829`) · KISTI NEURON A100-SXM4-80GB
· 분석 `cvpr27/code/analyze_a100.py --stage table`, `cvpr27/code/analyze_coc_quality.py --stage gate|table`
(`outputs/cvpr27/coc_quality/`) · 채점 `outputs/cvpr27/coc_judge/ood_coc_v1/`.

## Purpose
- **주행:** OOD-Val(262클립)에서 본 arm 순위가 5배 큰 long-tail 세트 OOD-train(1,271클립)에서도 유지되는지 본다.
- **CoC 품질:** 사람이 큐레이션한 정답 CoC를 기준으로, 각 arm이 맞는 추론을 내는지 두 방식으로 잰다.
  - 정답 CoC NLL: 모델이 정답 추론에 주는 확률
  - Claude 채점: 생성한 CoC가 정답과 같은 행동·원인을 말하는가
- 가설: 언어가 무너진 arm(Wanda-sp, Tyr, LLM-Pruner)은 두 지표 모두 MoOP보다 나쁘다.

## Setup
- **Arm 7개:** dense, MoOP(`dual_u40_v2`), MoOP l0keep, LLM-Pruner `lp_m24`, Tyr `tyr_off`, Tyr `tyr_vt`, Wanda-sp.
  압축 arm은 모두 제거 23.99%다. 모두 `calib_100`(OOD와 겹침 0)으로 보정했으므로 OOD-train은 오염되지 않았다.
- **세트:** OOD-train = `ood.parquet`에서 split == train인 1,271클립(OOD-Val과 겹침 0). 클러스터는 공사 구간 621,
  보행자 300, 특이 차량 171 등이다.
- **주행:** `run_baseline.py --set ood --manifest ood_train --no-tf`, k=8, 클립별 seed 42, arm당 4샤드. 짝지은 Δ는 부트스트랩 200,000회.
- **정답 CoC NLL:** `run_nll_gtcoc.py`. `[prompt] + gt_coc + <cot_end> + <traj_future_start>`를 forward 한 번 하고,
  덧붙인 구간의 토큰 평균 cross-entropy를 낸다. `run_baseline`의 `nll_gtcoc`과 같은 식이다.
  - **G1 게이트 PASS.** 비교 대상은 저장된 Ada 행이다(OOD-Val 262클립).

    | arm | 클립별 \|Δ\| 평균 | 평균 차 |
    |---|---|---|
    | dense | 0.0056 | +0.0001 |
    | MoOP | 0.0060 | −0.0002 |
- **Claude 채점:** `grade_coc_claude.py`, `claude-opus-5-5`, effort low.
  - 입력은 텍스트만이다(정답 + 생성 CoC). arm 이름은 보내지 않고, 순서는 섞는다.
  - 채점 항목: 행동 0–2, 원인 0–2, 모순, 정상 문장, 종합 1–5.
  - 대조:
    - 반복 채점 10%
    - 우연 바닥 `ctrl_mismatch`: dense CoC를 다른 클립의 정답과 짝지은 OOD-Val 262쌍
  - 거절 시 대체 모델 옵션(`fallbacks`)은 켰지만 실제로 쓰인 적은 없다.
  - 요청 12,008건, 실패 0, **비용 $31.42**(요청당 $0.0026).
- **실행:** NEURON 홀더 960229·960230(A100 4장씩).
  - 주행 28작업 + NLL 21작업, 실패 0, 약 27 A100-시간.
  - 11-02 23:10 – 11-03 04:43 KST.

## Analysis (Opinion)
- **채점은 주 지표로 쓸 만하고, 정답 CoC NLL은 Tyr에서 교란된다.**
  - Tyr 두 arm은 정답 CoC에 dense보다 높은 확률을 준다(NLL −0.08 ~ −0.14*).
  - 그런데 자기 CoC의 NLL은 0.31로 dense(0.21)보다 높다. 분포가 평평해져 정답 문장에도 확률을 나눠 주는 효과로 본다.
  - 실제 생성은 dense보다 나쁘다(채점 −0.30*). 따라서 NLL은 분포 날카로움이 비슷한 arm끼리(dense·MoOP·l0keep)만 비교한다.
- **압축은 OOD 추론을 조금 깎는다. MoOP 계열이 가장 적게 깎는다.**
  - OOD-train에서 MoOP −0.14*, MoOP l0keep −0.12*, tyr_vt −0.14*다. tyr_off −0.30*, LLM-Pruner −0.41*, Wanda-sp −1.7*보다 작다.
  - MoOP l0keep은 MoOP보다 채점 +0.027(경계), NLL −0.028*로 약간 낫다. 주행은 같다(+0.006 n.s.).
- **"tyr_off의 CoC는 멀쩡하다"(OOD-Val 결과)는 OOD-train에서 뒤집힌다.**
  - 표본이 5배인 OOD-train에서는 MoOP보다 −0.159*이고, 원인 일치가 25.6%로 가장 낮다(dense 33.4%).
  - V:T 1:1 헤시안(tyr_vt)은 CoC도 MoOP 수준(+0.004)으로 되돌린다. LingoQA 회복과 같은 방향이다.
- **tyr_off의 "주행 = dense"는 in-distribution에서만 성립한다.**
  - test2000에서는 MoOP보다 −0.075*였지만, OOD-train에서는 dense보다 +0.113*이고 MoOP와 같다(+0.018).
  - dense에 대한 KL로 맞춘 재구성이 보정 분포 밖에서는 이점을 잃는다고 본다. 폐루프 s600에서 tyr_off = dense였던 것과도
    맞춰 볼 만하다.
- **OOD-Val의 MoOP l0keep 대 MoOP 차(+0.063)는 표본 탓이었다.** OOD-train에서는 +0.006 (n.s.)이다.
- **dense조차 정답과 절반 이상 어긋난다(점수 3.05, ≥4가 41.5%).** OOD 장면에서 모델은 "앞차와 거리 유지" 같은 상투 CoC로
  돌아가고 long-tail 원인을 놓친다. 공사 구간이 특히 그렇다. 압축 비용보다 이 기저 격차가 더 크다.
