# kisti6(한강, GH200)를 두 번째 평가 사이트로

날짜: 2026-11-05. 상태: 계획 (승인 대기, 계정 정보 대기).

## 0. 목적

- NEURON A100 큐는 대기가 길다. 11-05 17:30 KST 기준 140개 작업(expx 60, ratio OOD-train 80)이 시작 전이다.
- 한강을 두 번째 GPU 사이트로 쓸 수 있게 만든다.
- 이 계획의 범위는 **접속 → 조사 → 전송 → 환경 → 검증**까지다.
  - 어떤 실험을 한강에서 돌릴지는 검증 결과(처리량, A100과의 차이)를 보고 따로 정한다.
- 지금 대기 중인 두 큐는 A100에 그대로 둔다(사용자 결정, 11-05).

## 2. 단계

### 2.1 접속

- cvlab21 `~/.ssh/config`에 `kisti6`(로그인)와 `kisti6-dm`(데이터무버)를 추가한다.
  - 인증 블록은 NEURON과 같다. OTP keyboard-interactive, pubkey 끔, ControlMaster, `ControlPersist 8h`.
  - 소켓 경로는 `~/.ssh/cm-kisti6-login`, `~/.ssh/cm-kisti6`.
- 소켓은 사용자가 `! ssh -fN kisti6`, `! ssh -fN kisti6-dm`으로 연다(OTP).
- 사용자명을 추측해서 시도하지 않는다. KISTI는 로그인 실패 시 계정을 잠근다.

### 2.2 조사 (읽기만)

- 로그인 노드: `uname -m`, `sinfo`, `scontrol show partition`, `sacctmgr show assoc/qos`(GPU 한도), `module avail`, `apptainer`/`enroot` 유무, 스크래치 경로와 `df`·쿼터.
- 인터넷: `github.com`, `huggingface.co`, `pypi.org`, `download.pytorch.org`를 로그인·데이터무버·계산 노드에서 각각 확인한다.
- 계산 노드 한 번(`srun` 1 GPU, 5분): `nvidia-smi`(GPU 메모리, 드라이버, CUDA 버전), CPU 코어 수.
- 결과는 이 문서 §5에 기록한다.

### 2.3 전송 (cvlab21 → `kisti6-dm`)

- NEURON과 같은 레이아웃: `/scratch/<USER>/{project, datasets/physicalai_av/pre_processed, checkpoints/hub, outputs}`.
  - 한강 스크래치 경로가 다르면 §2.2 결과에 맞춘다.
- `experiments/transfer/push_neuron.sh`를 그대로 쓴다. 접속 대상은 환경변수로 바꾼다.
  ```bash
  NEURON_DM=hangang-dm.ksc.re.kr NEURON_CM=~/.ssh/cm-kisti6 \
    bash experiments/transfer/push_neuron.sh <USER> code weights a100eval lingoqa
  ```
- OOD-train 캐시는 `a100eval` 등급에 없다. `ood` 네임스페이스(8.5 GB)를 따로 보낸다.
- NEURON → 한강 직접 전송은 하지 않는다(양쪽 다 OTP). 원본은 cvlab21이다.

| 묶음 | 크기 (`LIST_ONLY=1` 측정) |
|---|---|
| test_2000 + OOD-Val 262 캐시 | 12 GB |
| ood 네임스페이스 (OOD-train 1,271 포함) | 8.5 GB |
| Alpamayo 1.5 가중치 (rev 7aba8293) | 21 GB |
| Lingo-Judge 가중치 + LingoQA val | 1.2 GB |
| 레시피 (MoOP, MoOP l0keep) | 6.5 MB |
| 합계 | 약 43 GB + 코드 |

- 이후 arm 레시피는 실험마다 필요한 것만 보낸다(Tyr 계열은 `slim_state.pt` 포함, 약 13 GB씩).

### 2.4 환경 (aarch64)

- `build_venv_neuron.sh`를 복사해 `experiments/transfer/build_venv_kisti6.sh`를 만든다. 바뀌는 곳은 flash-attn 단계 하나다.
- Python 3.12는 uv가 관리하는 CPython을 쓴다(NEURON과 같음). 패키지는 `requirements_neuron.txt`의 고정 버전을 그대로 쓴다.
  - torch 2.8.0+cu128, transformers 4.57.1, triton 3.4.0, av 17.0.0, alpamayo1_5 @ f42e594.
  - aarch64용 wheel이 없는 패키지가 있으면 목록으로 보고하고 멈춘다.
- **flash-attn 2.8.3은 aarch64용 prebuilt wheel이 없다.**
  - 평가는 sdpa로 돌지만(`run_baseline.py:243`), 모델 `config.json`이 `flash_attention_2`를 요구해서 로드 단계에서 패키지가 있어야 한다.
  - 한강 계산 노드에서 소스 빌드한다. 대상은 sm_90 하나, `MAX_JOBS`는 노드 코어에 맞춘다. 만든 wheel은 스크래치에 저장해 재사용한다.
  - 데이터무버나 로그인 노드에서는 컴파일하지 않는다(NEURON 규칙과 같다고 가정하고 §2.2에서 확인).
- 대안(빌드가 막힐 때만, 사용자 결정): NGC PyTorch aarch64 컨테이너. 패키지 버전이 고정 버전과 달라진다.

### 2.5 평가 스크립트

- `eval_a100.sbatch`를 한강에서도 쓴다. 두 군데만 바꾼다.
  - 결과 루트를 변수로 만든다: `OUT_SITE=${OUT_SITE:-a100}` → `outputs/cvpr27/$OUT_SITE/...`. 기본값이 a100이라 NEURON 동작은 같다.
  - 파티션과 `--comment`는 sbatch 명령행에서 덮어쓴다(§2.2 결과).
- 한강 결과는 `outputs/cvpr27/gh200/` 아래에만 쓴다. 큐도 `outputs/cvpr27/gh200/queue_*`로 따로 둔다.

### 2.6 검증 게이트

| 게이트 | 내용 | 통과 조건 |
|---|---|---|
| G1 결정성 | dense test_2000의 125클립 조각(16분할 중 0번)을 같은 카드 종류에서 두 번 | 행 단위 bit-identical |
| G2 A100과의 차이 | G1 결과를 A100 dense 행과 클립 단위로 비교 | 통과 기준 없음. minADE@6·minFDE@6(1.6/3.2/6.4 s) 차이와 CoC 문장 변화율을 기록만 함 (참고: A100↔Ada dense ≤0.003 m, MoOP ≤0.018 m) |
| G3 slim 로드 | MoOP l0keep(마스크만)과 tyr_off(`slim_state.pt`) 같은 조각 | 에러 없이 돌고, 값이 A100과 같은 수준 |
| G4 처리량 | G1–G3의 클립/시간/GPU | A100과 비교해 기록 → 이후 작업 배분 근거 |

- 게이트 비용: 125클립 × 4회, GPU 1장으로 약 1–2시간(추정, G4에서 실측).

### 2.7 표 정책

- GH200 결과는 A100 표와 섞지 않는다(GPU 종류당 표 하나).
- GH200에서 비교하는 모든 arm은 dense를 포함해 GH200에서 다시 잰다.
- 보고서에는 GH200 블록을 따로 둔다.

## 3. 비용

- 전송 약 43 GB(+ 코드). 소요 시간은 cvlab21→한강 대역폭에 따른다.
- 환경 구축: flash-attn 빌드 포함 반나절 정도.
- 검증 GPU: 약 1–2 GPU-시간.
