# Experiment: AlpaSim score (사건당 주행 km), u40·u50 × Origin150·Hard100, ICLR 논문 arm

- 날짜: 2026-11-19 KST. 새 rollout은 없고, 저장된 런을 다시 집계했다.
- 코드: `code/alpasim_score_u40_u50.py`
- 결과:
  - 표: `outputs/iclr27-rebuttal/alpasim_score_u40_u50/table_seed{0,1}.md`
  - 수치: `outputs/iclr27-rebuttal/alpasim_score_u40_u50/metrics_seed{0,1}.json`
- 관련 보고서:
  - scene score 기준: `reports/2026-11-12_u50-closedloop-origin150-ci.md`, `reports/2026-11-18_u50-closedloop-hard100-ci.md`
  - u40 논문 표 재점검: `reports/2026-11-07_closedloop-ci-origin150-hard100.md`

## Purpose
- 지금까지 보고한 "score"는 rollout마다 매기는 **scene score**다(사건이 있으면 0, 없으면 진행률로 매긴 점수).
- 이 보고서는 이와 별개로, Alpamayo-R1 논문 §6.1과 Alpamayo 1.5 model card가 쓰는 **AlpaSim score**(사건 하나당 주행 km)를 같은 런들에서 계산해 정리한다.
- 대상: ICLR 논문 arm, u40과 u50, Origin150과 Hard100.

## Setup

| 항목 | 값 |
|---|---|
| 정의 | AlpaSim `eval/aggregation/processing.py:get_avg_dist_between_incidents`와 같다. scene마다 rollout을 `run_uuid_rollout_id` 순으로 1, 2번 인덱스로 나눈다. 인덱스별로 모든 scene의 주행 거리 합을 사건 수 합으로 나눠 km/사건을 구한다. 두 인덱스의 **평균 ± 표준편차(ddof 1)**를 보고한다 |
| 사건 | **at-fault** = 전방·측방 충돌 또는 offroad. 공개 벤치마크와 model card가 쓰는 쪽이다. **all** = 후방을 포함한 모든 충돌 또는 offroad |
| 주행 거리·사건 | `results-summary.json`의 rollout별 집계값을 쓴다. AlpaSim이 첫 사건 이후와 GT 경로에서 4 m 벗어난 이후의 시간 구간을 잘라낸 값이므로, rollout당 사건은 많아야 1개다 |
| 검증 | 샤드 하나(`u50h_slim_dual_u50_v2_sh1`)에서 AlpaSim이 직접 쓴 `metrics_results.txt`(1.47 ± 0.35 / 1.93 ± 0.30)와 같은 값이 나왔다 |
| 중단 rollout | 경로 정합성 검사로 중단된 rollout은 주행 기록이 없어 AlpaSim처럼 빠진다. scene score에서 0점으로 넣던 것과 다르다. Hard100의 시작 단계 중단 scene 2개는 어느 arm에도 기록이 없어서, Hard100은 98 scene으로 계산된다 |
| u40 런 | ICLR 런 `m2601_merged_*` / `h100_merged_*`, 인계 감속 수정 전 하네스. Origin150 LLM-Pruner u40은 런 폴더가 지워져 09-20 캐시(`outputs/alpasim_all_metrics/rollout_metrics.parquet`)를 썼다. 캐시에는 rollout_id가 없어 rollout 인덱스는 캐시 순서다 |
| u50 런 | `u50o_merged_*` / `u50h_merged_*`, 수정 후 하네스. dense는 u40과 같은 ICLR 런이다. MoOP+E는 u50 폐루프 런이 없다 |
| arm | dense, MoOP(`dual_u40_v2` / `dual_u50_v2`), MoOP+E(`dualexp_u40_em93p75`, u40만), FM-only, CE-only, Tyr(`tyr_u40_r` / `tyr_u50_r`), LLM-Pruner(`lp_r50` / `lp_r60`), Wanda |
| CI | scene을 통째로 다시 뽑는 부트스트랩, 2만 회, 같은 통계량. MoOP 대비 차이(MoOP − arm, 양수면 MoOP가 사건당 더 멀리 감)도 같은 재표집을 쓴다. 시드 0과 1에서 점추정과 유의성이 같다 |

## Analysis (Opinion)

1. **MoOP는 네 조건 중 세 곳에서 AlpaSim score가 가장 높다.**
   - Origin150 u40: at-fault 1.57, all 1.06. Origin150 u50: 1.80 / 1.32. Hard100 u50의 all 기준: 0.95.
   - Hard100 u40에서는 LLM-Pruner(1.15), MoOP+E(1.11)와 구분되지 않는다.
2. **u50에서는 차이가 뚜렷해진다.**
   - Origin150 u50: MoOP가 dense를 포함한 모든 arm보다 두 변형 모두 유의하게 높다.
   - Hard100 u50: dense, FM-only, CE-only, LLM-Pruner, Wanda보다 유의하게 높다.
   - u40에서는 at-fault 기준으로 대부분 유의하지 않았다. 사건이 arm당 25–70개뿐이라 at-fault CI가 ±0.5–1.5 km로 넓다.
3. **Tyr는 scene score와 같은 그림이다.**
   - Origin150 u50에서는 MoOP가 유의하게 높다(at-fault +0.94*).
   - Hard100 u50에서는 at-fault 기준으로 오히려 Tyr가 높은 쪽이지만(1.60 대 1.26, −0.34) 유의하지 않다. all 기준은 MoOP 0.95 대 Tyr 0.79로 유의하지 않다.
   - Hard100에서 Tyr의 offroad가 적은 것(scene score 보고서 0.140 대 0.195)이 at-fault 기준을 Tyr 쪽으로 끌어올린다.
4. **at-fault와 all은 순위를 다르게 매긴다.**
   - LLM-Pruner u40 Origin150은 at-fault 1.48로 MoOP에 가깝지만, all 기준은 0.70으로 유의하게 낮다. 후방 충돌이 많기 때문이다.
   - 공개 수치(at-fault) 하나만 보면 이런 차이가 가려지므로 두 변형을 함께 보고하는 편이 낫다.
5. **dense 대비 차이는 하네스 차이만으로 설명되지 않는다.**
   - u50 비교의 dense는 수정 전 하네스 런이다. 같은 수정 후 하네스의 dense로 바꿔도 Origin150에서 MoOP u50과의 차이는 at-fault +0.71*, all +0.58*로 남는다.
6. **비교하면 안 되는 것:**
   - u40 대 u50 MoOP 같은 예산 사이 절댓값 비교. 하네스가 다르다.
   - 이 값들과 Alpamayo 1.5 model card(1.37 ± 0.10, 913 scene). scene 집합, rollout 수, 하네스가 모두 다르다.
