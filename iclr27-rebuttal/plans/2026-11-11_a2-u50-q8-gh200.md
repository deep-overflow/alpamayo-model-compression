# Plan: Alpamayo 2 Super u50 with fewer Q heads cut (q8), test500 · OOD-Val262 · OOD-train1271 on KISTI GH200

Status: **draft, awaiting approval** (user ask 2026-11-11).

User ask: "kisti6에서 u50에서 Q head는 덜 자르고 MLP를 더 자르는 버전으로 만들어서 test500, ood-val, ood-train을 평가하려고 하는데
계획 세워줘."

User decisions (2026-11-11):

- Q heads cut per layer: **8 of 64**. This is 12.5%, the same fraction as A1.5's `dual_u40_qcut4_v2`.
- Criteria: **MoOP, FM-only and CE-only all three**.

## Purpose

Hypotheses:

- **H1.** At A2 u50's budget, MoOP drives better in open loop when the cut moves from Q heads to MLP channels.
  - Precedent: A1.5 `dual+h4` (same budget, 4/32 heads instead of 13/32), whose numbers are in Background.
- **H2.** The u50 gap MoOP − FM-only = +0.077* (test500, Blackwell) depends on the allocation. If it comes from the Q-head part of the selection, keeping most heads should close it.
  - Mask overlap says MoOP and FM-only differ mostly in layers 32-63 MLP, which q8 cuts *more* of, so it may widen instead.
- **H3.** CE-only's u50 damage is head-driven: +50.9%, CoC degeneracy 4.6%. Keeping 56/64 heads should reduce both.

Background:

- A1.5 `dual+h4` vs `dual` in open loop: −0.039 / −0.039 / −0.085 on val500 / test500 / OOD, all n.s. on the mean. CoC degeneracy went to 0.
- The same pair in closed loop was **worse**: −0.091*, offroad 6.7% → 9.3% ([[head-vs-mlp-openloop-closedloop-split]] in memory).
- Closed loop cannot run on Hangang because the NuRec renderer image is amd64-only. **So this plan answers the open-loop question only**, and the report must say so.

**Budget arithmetic**

- One Q head = 2·128·5120 = 1,310,720 params. One MLP channel = 3·5120 = 15,360 params, so one head = 85.33 channels.
- u50 per layer = 32 heads + 12,800 channels = 238,551,040.
- q8 per layer = 8·1,310,720 + 14,848·15,360 = 10,485,760 + 228,065,280 = 238,551,040. This is identical; budgets match exactly only when (32 − q) is a multiple of 3.
- q8 keeps 56/64 heads and 10,752/25,600 channels (42%).

**Why the uniform u50 arms are re-run**

- They are the same-hardware reference for the q8 arms.
- u50 has only been measured on test500 on Blackwell. OOD has never been measured.

**Selection.** Same scores as before (`a2_importance_v1`, calib_100, within-layer rank_norm; MoOP = max of the two ranks) and the same `select_mask_ratios`. Only the per-axis counts change. This is make_slim's `_qcut<N>` rule: the channel count is derived from the budget, and an assert refuses anything that does not divide exactly.

## Protocol

Identical to the u40 OOD run (`2026-11-10_a2-u40-ood-gh200.md`):

- `run_a2_openloop.py`, 1 CoC rollout + k=8, seed sha256(42:clip_id), max_gen 256.
- minADE@6 / minFDE@6 at 1.6 / 3.2 / 6.4 s, CoC degeneracy.
- Paired Δ with 200k bootstrap and Wilcoxon.

**Readouts (all within GH200)**

- each arm − dense
- **q8 − u50 per criterion** (H1, H3)
- MoOP − FM-only and MoOP − CE-only within each allocation (H2)
- OOD only: u50 − u40, against the GH200 u40 rows from job 1251209
- Context only: the Blackwell test500 u50 rows

## Code changes (after approval)

1. `make_a2_moop_masks.py --pct 50 --q-cut 8`
   - Writes `masks_{moop,fm_only,ce_only}_u50_q8.npz` and `masks_config_u50_q8.json`.
   - The per-layer budget comes from the `--pct` path; the MLP count is derived with make_slim's divisibility assert.
2. `a2_ood_gh200.sbatch`
   - Masks are looked up generically as `masks/masks_<arm>.npz`. `moop` resolves to the existing u40 file, so u40 behaviour is unchanged.
   - Adds the set `test500` (manifest `test_500`, cache `test500_a2`).
   - Adds a `QUEUE` env so this run uses `queue_u50q8/`, its own gate and claims.
   - Adds a `GATE_MASKS` env, set to MoOP u50-q8.
3. `launch_a2_ood_gh200.sh`
   - New env: `ARMS` (default = the u40 arms), `SETS` (adds `test500`), `QUEUE`.
   - G0 learns the expected cut counts per suffix: u40 1,664 / 652,992; u50 2,048 / 819,200; u50_q8 512 / 950,272.
4. `push_a2_ood_gh200.sh`
   - New part `test500`: cache `test500_a2` (500 samples, 4.72 GB) and manifest `test_500.parquet`.
   - `MASK_ARMS` env selects which masks to push.
5. `analyze_a2_test500.py`
   - New presets `u50q8_test500`, `u50q8_oodval`, `u50q8_oodtrain` with the arms and pairs above.
   - The existing presets must reproduce byte for byte.

## Gates

- **G0a (cvlab21).** The mask builder still reproduces A1.5's shipped kept sets unit for unit:
  - u40 ×4, u20, u30 (as now)
  - **plus `slim_dual_u40_qcut4_v2`** (u40 ratio, 4 Q heads cut), the A1.5 twin of this allocation.
- **G0b (cvlab21).** For each criterion the q8 masks:
  - cut exactly 8 heads and 14,848 channels in every layer, removing 15,267,266,560;
  - nest with u50: q8's cut heads ⊂ u50's cut heads, and u50's cut channels ⊂ q8's cut channels (same ranking, other counts);
  - satisfy the rank-order check (every kept unit outranks every cut one).
- **G0c (Hangang).** Before submitting:
  - every file is present;
  - manifests are 500 / 262 / 1271 with no cache file missing;
  - masks have the expected cut counts;
  - import works;
  - /appsdata has more than 20k free files.
- **G1 (GH200, first thing in the holder).** On 2 OOD-Val clips:
  - all-ones hooks are bitwise equal to no hooks;
  - the q8 MoOP masks change the output;
  - dense ends with EOS.
  - **Also:** the gate's no-hook rows must equal job 1251209's stored dense rows for those clips bitwise. This is the check that licenses reusing the OOD dense rows.

## Compute

- **Work**
  - 6 masked arms × (500 + 262 + 1271) = 12,198 clip-runs, plus dense test500 500 = **12,698 clip-runs**.
  - At 9.57 s per GH200 (measured 11-10) that is ~33.8 GPU-h.
- **Queue.** 50 lines: test500 in 2 shards, OOD-Val in 2, OOD-train in 4. Ordered test500 → OOD-Val → OOD-train, so sets finish one at a time.
- **Holders**
  - One 4-GPU holder needs **~8.7 h** (`HOLDER_TIME=12:00:00`), two need ~4.4 h.
  - The submit limit is 5 per user and the user's lance holders held 4 on 11-10. The number of holders is decided at launch from `squeue`: 1 by default, 2 only if a second slot is free.
- **Transfer.** test500 cache, 4.72 GB, about 2-5 min. Six mask files, 6.6 MB each.
- **Finish.** Done holders are scancelled. They otherwise idle for IDLE_MAX = 2 h.

- **Open loop only.** In A1.5 the same move looked neutral to good in open loop and was clearly worse in closed loop. A q8 win here is not a driving claim.
- **One draw.** There is one calibration draw and one importance measurement.
- **Hardware.** GH200 rows are not merged with the Ada / Blackwell tables.
