# Plan: Alpamayo 2 Super u40 on OOD-Val262 and OOD-train1271, KISTI Hangang GH200

Status: in progress (user ask 2026-11-10). Follows `2026-11-09_a2-moop-test500.md` (u40, test500, Ada).

## Purpose

- **User ask (11-10):** "u40에 대해 MoOP, FM only, CE only에서 OOD-val OOD-train을 진행해줘. kisti6 서버 사용하려고 해."
- **Dense is included.** It was answered and agreed in the same exchange. There is no A2 dense OOD row yet, and on GH200 the deltas need a dense measured on the same card type: GH200 vs A100 moved dense by +0.004 m, and CoC differed on 2-7% of clips.
- **Questions**
  - Does the test500 picture hold out of distribution? On test500, MoOP ≈ FM-only (+0.007 n.s.) and both beat CE-only (−0.074*).
  - How does the A2 cost compare with A1.5's on the same sets?

## Setup

- **Arms.** The test500 run's masks are reused unchanged: `outputs/iclr27-rebuttal/a2_moop/masks_{moop,fm_only,ce_only}.npz`.
  - Q 26/64 and MLP 10,203/25,600 cut in every VLM layer, 34.1% of A2.
  - Dense uses no hooks.
- **Sets**
  - OOD-Val262: manifest `ood_val`, A2 cache `ood_a2`, built earlier by alpamayo2-distill.
  - OOD-train1271: manifest `ood_train`, A2 cache `ood_train_a2`, built 11-10 on cvlab21 with `build_cache_a2.py --old-cache-name ood`.
- **Protocol.** Identical to test500 (`run_a2_openloop.py`): 1 CoC rollout + k=8, seed sha256(42:clip_id), max_gen 256.
  - Readouts: minADE@6 / minFDE@6 at 1.6 / 3.2 / 6.4 s and CoC degeneracy.
  - Statistics: paired Δ with 200k bootstrap and Wilcoxon.
- **Hardware.** KISTI Hangang 5thEx, GH200 120 GB.
  - One A2 replica per card, so the whole model sits on one card (72 GB peak on the Ada pair).
  - All four arms run on GH200. These rows are never merged into the Ada / Blackwell tables.

## Infrastructure

- **Storage.** Everything is under `/appsdata/e1997a06/a2_ood`, because the group `/scratch` file quota was 4,992,985 / 5,000,000 on 11-10. `/appsdata` was at 30%.
  - `code/amc`: runner, sbatch, eval_lib, eval_sets
  - `code/a2d`: alpamayo2-distill `src` + `experiments/oodval`
  - `hub`: A2 rev 00554695, 29 blobs
  - `data`: the two caches
  - `masks`
  - `outputs`, `queue`, `logs`
- **Environment.** No new venv. The `/scratch` aarch64 venv already has A2's pins: torch 2.8.0+cu129, transformers 4.57.1, flash-attn 2.8.3, accelerate 1.14, physical_ai_av 0.2.0. `alpamayo2_super` is put on sys.path from `code/a2d/src`.
- **Code changes**
  - `run_a2_openloop.py`:
    - `--manifest`, `--set-name`
    - one visible card puts the whole model on `cuda:0`
    - `A2_DISTILL` path
    - absolute `--exp-id`
  - `analyze_a2_test500.py`:
    - presets `u40_oodval` and `u40_oodtrain` (n = 262 / 1271)
    - A1.5 context: OOD-train from the 11-09 GH200 run, OOD-Val from the paper's Ada rows
- **New scripts**
  - `push_a2_ood_gh200.sh` (cvlab21 → hangang-dm, with checksums)
  - `launch_a2_ood_gh200.sh` (G0 on glogin, queue, sbatch)
  - `a2_ood_gh200.sbatch` (gate G1, then 4 workers with mkdir claims, like `cvpr27/code/eval_a100.sbatch`)
  - `pull_a2_ood_gh200.sh`
- **Queue.** 24 lines `<arm> <set> <shard> <n>`.
  - OOD-Val first, 2 shards per arm.
  - Then OOD-train, 4 shards per arm.
  - Dense goes first in each set.
- **Holders.** One 4-GPU holder, `--time=10:00:00`. The user's lance holders occupy 4 of the 5 submit slots.

## Gates

- **G0, cvlab21 side (push)**
  - code md5, masks sha256
  - model blobs and cache files equal in name and size
  - the OOD-train cache has 1271 / 1271 samples before it is pushed
- **G0, Hangang side (launch)**
  - more than 20k free files on `/appsdata`
  - all files present, 15 shards resolve
  - masks cut 1664 Q heads / 652,992 channels
  - manifests are 262 / 1271 with no cache file missing
  - `alpamayo2_super` imports
- **G1 (holder, GH200).** First 2 OOD-Val clips:
  - all-ones hooks are bitwise equal to no hooks
  - MoOP masks change the output
  - dense ends with EOS
- **Analysis regression.** The `--preset u40` rerun is byte-identical to the existing test500 metrics (checked 11-10).

## Cost

- 6,132 clip-runs.
- At ~10 s/clip per GH200 (unmeasured; the Ada pair ran 13.7 s), that is about 17 GPU-h, roughly 4.5 h on one 4-GPU holder, plus queue wait.
