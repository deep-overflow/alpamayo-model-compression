# 계획: u50(29.98% 제거)에서 MoOP · Tyr · LLM-Pruner s600 폐루프 (cvlab21)

2026-11-09 · 상태: **승인 대기** · 결과는 `iclr27-rebuttal/`에 정리

## 목적

- **배경:** u40(23.99%)의 s600 폐루프에서 MoOP는 논문 Tyr 행·LLM-Pruner와 scene score로 구별되지 않았다.
  - 논문 Tyr − MoOP는 +0.017 [−0.007, +0.040]이었다.
  - LLM-Pruner − MoOP는 −0.011 [−0.040, +0.019]이었다.
- **개루프 비율 실험(`cvpr27/reports/2026-11-05_baselines-ratio-sweep.md`, A100):** u50에서는 MoOP l0keep이 두 기준선보다 확실히 낫다.
  - Tyr: test_2000 +0.044*, OOD-Val +0.224*, OOD-train +0.297*
  - LLM-Pruner: test_2000 +1.461*, CoC 퇴화 74.5%
- **가설:**
  - H1: u50에서는 폐루프 scene score도 MoOP l0keep이 Tyr보다 높다. 씬 짝 차이의 CI가 0을 포함하지 않는다고 본다.
  - H2: 같은 조건에서 MoOP l0keep이 LLM-Pruner보다도 높다.
- **부수 질문:** 각 방법이 u40에서 u50으로 갈 때 폐루프가 얼마나 떨어지는가. u40 점은 이미 s600에 있다.
- **반증 조건:** u50에서도 CI가 0을 포함하면 "폐루프 차이는 압축이 세져도 안 보인다"로 보고한다.
  개루프-폐루프 해리는 이미 여러 번 봤다. 예를 들어 u40에서 LLM-Pruner는 개루프 +0.409 m였지만 폐루프 score는 같았다.

## arm (사용자 범위: MoOP, Tyr, LLM-Pruner만)

| arm | 레시피 | 제거 파라미터 | 상태 | 비교할 u40 s600 런 |
|---|---|---|---|---|
| MoOP l0keep u50 | `dual_u50_l0keep_v2` (`make_slim.py`, calib_100 중요도) | 3,321,888,768 − 4,096–8,192 | cvlab21에 레시피 없음. NEURON에서 `--no-state`로 빌드했다 → 여기서 다시 빌드 | `l600_merged_slim_dual_u40_l0keep_v2` (0.774) |
| Tyr u50 | `outputs/cvpr27/slim_tyr_u50` (공식 절차, KL 적합도, 30번 층 Q head 전부 제거) | 3,321,888,768 | `slim_state.pt` 15 GB 있음 | `tyo_merged_slim_tyr_off` (0.738) |
| LLM-Pruner u50 | `outputs/cvpr27/slim_lp_u50` (Q head 단위, 4–33번 층, `coc_param_first`) | 3,321,888,768 | 레시피만 있음 → `slim_state.pt` 생성 | `p24_merged_slim_lp_m24` (0.766) |

- 대조군 dense는 `s600_merged_baseline`(0.729)을 그대로 쓴다.
- 비율 실험의 u50 arm과 같은 빌드를 쓰므로 개루프 숫자와 바로 이어진다.

**주의할 교란 요인:**
- **Tyr u50은 공식 절차판이다.** u40 공식판 `tyr_off`와 같은 계열이고, 논문 Tyr 행 `tyr_u40_r`(간이 포트)과는 다르다.
  - u40 s600에서 공식판은 MoOP l0keep보다 −0.035*였고, 포트판은 +0.009(n.s.)였다.
  - 그래서 u50 결과는 "논문 Tyr 행"이 아니라 "Tyr 공식 절차"와의 비교다(아래 질문 1).
- **LLM-Pruner u50은 예산을 MoOP에 맞춘 판이다(`lp_m24` 계열).** 논문 행 `lp_r50`과는 다르다.
  u40 s600에서 두 판의 차이는 −0.011(n.s.)이었다.
- **MoOP는 l0keep판이다.** 논문 MoOP(`dual_u40_v2`)와는 다르다. u40 s600에서 두 판의 차이는 +0.008(n.s.)이었다.

## 절차

0. **준비.** GPU를 쓰지 않는다. 지금 바로 할 수 있다.
   - `slim_lib.load_slim` → `save_slim(write_state=True)`를 CPU에서 실행해 MoOP u50과 LLM-Pruner u50의 `slim_state.pt`를 만든다.
     MoOP 레시피는 `make_slim.py --config dual_u50_l0keep_v2 --no-state`로 다시 만든다.
   - **G0:**
     - MoOP u50 레시피가 A100 평가에 쓴 NEURON 사본과 유닛 단위로 같아야 한다. NEURON 소켓이 없으면, 같은 코드로 `dual_u40_l0keep_v2`를 다시 빌드해 기존 레시피와 같은지로 대신 확인한다.
     - 제거 파라미터 수가 예산과 맞아야 한다.
     - 세 드라이버 모두 AlpaSim 로더(`alpamayo1_5_slim.load_slim`)로 읽혀야 한다.
   - 세 체크포인트를 `alpasim/data/drivers/`에 하드링크한다(`cp -al`).
1. **대기.**
   - 지금 쓰고 있는 A2 u50(Blackwell 0–3)과 ada-fill(Ada 4–7) 런처가 모두 끝나야 한다.
   - 그리고 카드 8장이 모두 비어야 한다(10 MiB 이하).
   - 작업 사이 잠깐 빈 틈에는 띄우지 않는다.
2. **arm마다 진행.** `run_dual_s600.sh`(STAGE=smoke → 게이트 → main)를 쓴다.
   - smoke는 8씬이고, `s600_smoke_gates.py`의 G1·G2를 통과해야 main으로 넘어간다.
   - main은 592씬이고, 각 씬을 dense 기준선과 같은 카드에서 돌린다(u40 점들과 같은 배치).
   - 순서는 MoOP → Tyr → LLM-Pruner다. CoC 퇴화가 큰 LLM-Pruner가 가장 느리므로 마지막에 둔다.
   - 하네스는 인계 감속 수정이 들어간 판이다. 끝나면 우리 docker 컨테이너와 네트워크를 정리한다.
3. **분석.** `analyze_dual_s600.py`(912씬 층 가중 부트스트랩)로 다음을 비교한다.
   - 주 비교: Tyr u50 − MoOP u50, LLM-Pruner u50 − MoOP u50
   - 보조: 각 u50 − dense, 각 u50 − 자기 u40 런
   - 지표:
     - scene score와 함께 progress, 과실 충돌, 전체 충돌, offroad, plan deviation, CoC 퇴화
     - AlpaSim score(km/사건, at-fault·all; `alpasim_score_s600.py`)
     - 실패 계열(offroad형 대 과실 충돌형)
   - score만 단독으로 보고하지 않는다.
4. **보고.**
   - `iclr27-rebuttal/reports/2026-11-1x_u50-closedloop-s600.md`
   - 결과 `outputs/iclr27-rebuttal/u50_s600/`
   - 런 `alpasim-runs/u50{m,t,l}_*`
   - README 갱신, main 커밋

## 비용과 일정

- 준비: CPU 빌드 2개, 약 30–60분. 디스크는 약 31 GB가 늘어난다(현재 1.2 TB 여유).
- GPU: arm마다 카드 8장.
  - MoOP·Tyr는 약 7시간씩이다(u40 Tyr 6.9시간 기준).
  - LLM-Pruner는 CoC 퇴화 74.5%라 12–18시간으로 본다(u40 Wanda-sp는 퇴화 75%에 17.6시간).
  - 합계 약 26–32시간이다.
- 시작은 현재 cvlab21 작업이 끝난 뒤다. 그때까지 카드 8장을 다른 작업에 쓸 수 없다.

## 사용자에게 확인할 것

1. **Tyr u50 판.**
   - 기본은 이미 있는 공식 절차판 `slim_tyr_u50`이다. 개루프 비율 실험과 같은 빌드다.
   - 논문 Tyr 행과 맞추려면 간이 포트판 u50을 새로 빌드해야 한다. 개루프 수치가 없고, 빌드 시간과 개루프 평가가 추가로 든다.
2. **일정.** 현재 cvlab21 작업이 끝나면 자동으로 시작하는 게 기본이다. 다른 시각을 원하면 알려 달라.
