# Plan: MoOP vs FM-only vs CE-only on Alpamayo 2 Edge at u40 (LingoQA, Test500, OOD-Val)

2026-11-14. User ask: compare MoOP, CE-only and FM-only on Alpamayo 2 Edge on LingoQA, Test500 and OOD-Val, starting
with u40.

Prior work:
- The importance was measured in `plans/2026-11-14_a2-edge-analysis-replication.md` (done, calib_100).
- The recipe and evaluation follow the A2 Super u40 study: `plans/2026-11-09_a2-moop-test500.md`,
  `plans/2026-11-13_a2-lingoqa.md`.

## Hypotheses

- **H1 (driving, open loop).** Does MoOP drive better than FM-only and CE-only (minADE@6 / minFDE@6) on Test500 and
  OOD-Val?
  - On A2 Super at u40, MoOP was equal to FM-only and better than CE-only.
  - The Edge analysis gives a reason to expect more separation: I_FM and I_CE already rank Q heads differently in early
    layers (pre-step rho 0.49, against 0.88 on A2 Super). FM-only and CE-only should therefore remove more different
    heads.
- **H2 (language).** On LingoQA, does MoOP keep more language ability than FM-only, and as much as CE-only?
- Every arm is also compared with dense Edge.

Not pre-registered. This is the first u40 look, like A2's 2026-11-09 study. A confirmatory test can follow.

## Setup

**Importance.** `outputs/iclr27-rebuttal/edge_importance_v1`: calib_100 (100 clips, t0 5.1 s), no-nav prompt, dual
objective. It has the same file layout as a2_importance_v1.

**Masks.** `make_a2_moop_masks.moop_masks`, imported unchanged, with Edge's sizes:
- Scores:
  - MoOP = max(rank_norm(I_FM), rank_norm(I_CE)) within each layer
  - FM-only = rank_norm(I_FM)
  - CE-only = rank_norm(I_CE)
- Ratio: u40 = make_slim's matched ratio 0.3985632694 in every layer, the A2 rule (decision D1 of the A2 plan).
- Per layer, Edge removes **6 of 16 Q heads** and **3,673 of 9,216 MLP channels**.
- Edge's MLP is relu^2 (fc1 + fc2, no gate), so a channel costs 2 x hidden parameters, not 3 x as in A2's bookkeeping.
- Removed in total:
  - per layer: 6 x 524,288 + 3,673 x 4,096 = 18.19 M
  - over 28 layers: **509 M = 19.2 % of Edge's 2.65 B**, or 36.1 % of the VLM text decoder layers.
  - The share of the total is smaller than A2's 34.1 % because embeddings, vision and expert weigh more in a 2.65 B
    model.
- Untouched: the expert, the KV heads, the vision tower and the embeddings.
- No l0keep arm. You asked for three arms, and all three come from one importance measurement, so the
  calibration-draw variance that l0keep removes (CLAUDE.md) does not enter these comparisons.
- Gates:
  - G0: the imported function's own regression (A1.5 importance_v2 -> the shipped dual / traj / coc u40 kept sets,
    unit for unit) passes.
  - Each Edge mask has exactly 6 Q heads and 3,673 channels removed per layer.

**Arms.** dense, MoOP, FM-only, CE-only.

**Applying masks.**
- Forward pre-hooks that zero the masked inputs: Q heads at `self_attn.o_proj`, MLP channels at `mlp.fc2`. This is the
  same as `run_a2_openloop.VlmMasks`, with fc2 in place of down_proj.
- G1 (3 clips / 3 questions):
  - all-ones hooks are bitwise equal to no hooks
  - the masks change the output

**Open-loop protocol.** A2's `run_oodval.rollout_then_k_traj` protocol, on Edge:
- One CoC rollout: release sampling (T 0.6, top_p 0.98, max 256), seed `sha256("42:clip")[:4]`.
- Then K = 8 denoisings on that rollout's KV cache, 10 Euler steps, seed base + k.
- Edge's own generation path: trajectory vocab masked, text EOS blocked, `StopAfterEOS(<|traj_future_start|>)`, no-nav
  prompt.
- Metrics (eval_lib, like A2):
  - minADE@6 and minFDE@6 (first 6 of the 8 samples) at 1.6 / 3.2 / 6.4 s
  - @8 as a side number
  - CoC degeneration
  - the `<NOMINAL>` rate

**Clip sets.**
- **Test500:** `outputs/eval_sets/test_500.parquet`, 500 clips, all at t0 5.1 s.
- **OOD-Val:** `outputs/eval_sets/ood_val.parquet`, 262 clips at their event timestamps. **12 of them have t0 < 2.0 s.**
  Edge's input profile needs a front frame at t0 - 2 s, so its loader refuses those clips. See Q1.

**Edge input caches.** Built with `build_edge_calib_cache.py --manifest ... --root ...` (streamed from the Hub, no
navigation stored):
- `physicalai_av/pre_processed/test500_edge`
- `physicalai_av/pre_processed/oodval_edge`
- Gate: the GT future and the last 16 history poses equal A2's `test500_a2` / `ood_a2` caches.

**LingoQA.** The 500 val questions (100 segments x 5), the same as the A2 and A1.5 runs.
- Prompt: Edge's native VQA conversation (`chat_template.build_vqa_conversation`, a no-thinking assistant prefix), with
  the **front camera only**:
  - the last 4 of LingoQA's 5 frames
  - camera label "Front camera:"
  - time labels `<t=-3.0s> <t=-2.0s> <t=-1.0s> <t=0.0s>`
  - pixel bounds 163,840-196,608
- Why the time labels: the LingoQA paper says "a 4-second video clip at 1 Hz", 5 frames, so the spacing is inferred as
  1 s. No source gives exact timestamps.
- Edge's VQA input check insists on 6 cameras x 4 frames. The front-only conversation is built directly, mirroring the
  A2 port (front camera, 4 frames).
- Decoding: greedy, max 128 new tokens, stop at EOS or the trajectory anchor (Edge's `text_tasks.generate_vqa_answer`).
- Scoring: `experiments/lingoqa/score_lingo_vqa.py` (Lingo-Judge).

**Statistics.** The machinery of `ci_openloop_lingoqa.py`:
- 200,000 bootstrap draws, seed 0, shared draws across arms.
- Open loop: clip-level paired CIs. LingoQA: CIs resample the 100 segments.
- Reported: absolute values per arm, then arm - dense, MoOP - FM-only and MoOP - CE-only, each with 95 % CI and
  two-sided bootstrap p.

**Hardware.**
- **Blackwell cards 2 and 3 (RTX PRO 5000) only (user, 2026-11-14).** The user first said cards 0-3, then 2-3 only.
  One GPU type for the whole table: every arm and every set runs on Blackwell.
- Empty cards only: `nvidia-smi` is checked in a separate step right before each launch.
- The 3-clip open-loop G1 gate ran on card 0 before the change and finished. It was launched in the same command as the
  check, while another job had just taken the card.
- Several of my own processes may share one card (about 10 GB each).

## Steps

1. Masks + G0: `code/make_edge_moop_masks.py`
   -> `outputs/iclr27-rebuttal/edge_moop/masks_{moop,fm_only,ce_only}.npz` + config.
2. Edge caches for Test500 (500) and OOD-Val (250 or per Q1) + GT gate.
3. Runners:
   - `code/run_edge_openloop.py`
   - `code/run_edge_lingoqa.py`
   - G1 on each
4. Runs: 4 arms x (500 + 250 clips) and 4 arms x 500 questions.
   - Output directories: `outputs/iclr27-rebuttal/edge_{test500,oodval,lingo}_{dense,moop,fm_only,ce_only}/`
   - Each has config.json, metrics.json, summary.txt and per-clip records.
5. Scoring, CIs, report.
   - Report: `reports/2026-11-1X_a2-edge-moop-u40.md`, facts and analysis separated.
   - Open-loop tables at all three horizons, absolute values first.
   - README index row.

## Decisions

- **Q1. OOD-Val: evaluate on the 250 clips with t0 >= 2.0 s (user, 2026-11-14).**
  - The manifest is `outputs/iclr27-rebuttal/edge_moop/ood_val_250.parquet`. All four arms use the same 250 clips.
  - Absolute numbers are not directly comparable with A2 / A1.5's OOD-Val262.
  - Rejected alternatives:
    - moving t0 to 2.0 s (it changes the event timestamp)
    - padding the missing front frame (it leaves Edge's input profile)
